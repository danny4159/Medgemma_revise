  - 비전 인코더: SigLIP. 전 모달리티가 동일 weight 공유. 모달리티별 expert 없음.

5. 추론 방식 (공식 형식 3종)
================================================================================
공통 로딩: dtype=bfloat16, device_map/device=cuda, do_sample=False (greedy, 결정적)

--------------------------------------------------------------------------------
[형식 A] 일반 2D — pipeline API (모델 카드 예시)
--------------------------------------------------------------------------------
  pipeline("image-text-to-text")
  messages=[{"role":"user","content":[{"type":"image","image":PIL},
                                      {"type":"text","text":prompt}]}]
  용도: 그룹 1/2 평가, 진단 실험 대부분

--------------------------------------------------------------------------------
[형식 B] 위치 추정 — detect + box_2d  (1.5 공식)
--------------------------------------------------------------------------------
  프롬프트:
    Detect the {object}. Output a JSON list where each entry contains the
    2D bounding box in "box_2d" and a text label in "label".
  출력:
    ```json
    [{"box_2d": [y0, x0, y1, x1], "label": "right lung"}]
    ```
  좌표 규약: **y 먼저**, **0~1000 스케일**

  형식 확정 방법 (추측하지 않고 실측):
    1) 형식 지시 없이 "Where is the right lung?" -> 산문만 나옴. 박스 없음.
    2) 후보 프롬프트 5종을 비교 -> Gemma 3 계열 detect 문구에서만 JSON 박스 출력.
    3) 좌표 순서·스케일은 기하가 알려진 대상으로 검증:
       같은 흉부 X-ray에서 "right lung"과 "left lung"을 각각 검출시켜,
       3장 모두 우폐 박스 중심 x가 좌폐보다 작음(=영상 왼쪽)을 확인.
       PA 흉부영상의 방사선학적 관례와 일치하므로 [y0,x0,y1,x1] 해석이 맞음.

--------------------------------------------------------------------------------
[형식 C] 3D CT/MRI — 다중 슬라이스 블록  (공식 CT 노트북)
--------------------------------------------------------------------------------
  1) 볼륨에서 최대 85장을 균등 샘플링 (MAX_SLICE=85)
  2) CT는 HU 3중 윈도우를 RGB 채널로 인코딩:
       R (-1024, 1024) 광역 / G (-135, 215) 연부조직 / B (0, 80) 뇌
       각 채널을 선형 정규화해 0~255
     (MRI는 HU 개념이 없어 볼륨별 1~99 퍼센타일 윈도잉 후 RGB 복제)
  3) 한 user 턴에 교차 배치:
       text(상황 설명 instruction)
       -> [image(slice1), text("SLICE 1"), image(slice2), text("SLICE 2"), ...]
       -> text(질의)
  4) processor.apply_chat_template(add_generation_prompt=True, tokenize=True,
                                   return_dict=True) -> model.generate(do_sample=False)
     -> processor.post_process_image_text_to_text 로 디코드 후 입력부 제거

  출처: github.com/google-health/medgemma 의 high_dimensional_ct 노트북을
        직접 내려받아 코드 셀에서 추출 (모델 카드가 "CT/MRI는 전처리가 필요하니
        이 노트북을 보라"고 안내).

--------------------------------------------------------------------------------
[E-A] 본 평가 542 태스크 (형식 A)
--------------------------------------------------------------------------------
그룹 1 (자유서술 QA, 102): vqa_rad 10 / slake 82 / kvasir 10
  meta의 question을 그대로 사용하고, 정답이 단어~짧은 구이므로
  "Answer with a single word or a short phrase only"를 덧붙임
  (이 지시가 없으면 장황한 답변 탓에 token F1이 부당하게 낮아짐 — 사전 확인 후 적용)

[프롬프트 민감도 — 비공식 형식을 썼을 때]

  판단: 이것들은 모델 능력의 부재가 아니라 **비지원 출력 형식에서의 퇴화 동작**이다.

[자연어 유도 — 형식을 완화했을 때]
  선택지를 제시하지 않는 빈칸 채우기("The lesion is in the ___ half")로 물으면
    실제 병변 좌우: 방사선학적 관례 기준 18/24 = 75% (p=0.011)
                    영상 좌표 기준으로 채점하면 6/24 = 25% (체계적 반전)
    실제 병변 상하: 13/17 = 76% (p=0.025)
    3분할(좌/중/우): 7/30 = 0.23 — 우연(0.33) 수준, 유의하지 않음

  판단 1: 모델은 좌우를 **환자 기준(방사선학적 관례)**으로 답하며, 프롬프트에

  판단 2: 자연어로 얻을 수 있는 공간 정보는 축당 약 1비트(절반 단위)가 한계.
          3분할부터는 신뢰할 수 없다.

  판단: 모델은 내용이 없다는 것을 **인지할 수 있다**. 중립적으로 물으면 정확히 답한다.
        문제는 프롬프트의 거짓 전제에 반박하지 않는 것이다.
        -> 프롬프트에 탈출구 한 줄을 넣는 것만으로 해결된다 (효과 확인됨, 비용 0).

[긍정 편향 — 가설 반증됨]
  있을 수 없는 소견 30건(뇌종양/충치/대퇴골 골절) -> yes 0건
  부정형 표현 30건                                 -> 26/30 정확
  이진 질문 전체 yes 비율                          -> chexpert 0.231, nih 0.182
  판단: 무분별하게 yes라고 하지 않으며 표현 트릭에도 흔들리지 않는다.
        "소견을 과다 호출한다"는 초기 가설은 틀렸다.

[낮은 정밀도의 원인 — 기저율]
  chexpert: 유병률 16/130=0.123, 민감도 .500, 특이도 .807
            -> 공식 예측 정밀도 0.267 / 실측 0.267 (일치)
  nih     : 유병률 13/132=0.098, 민감도 .308, 특이도 .832
            -> 공식 예측 0.167 / 실측 0.167 (일치)
  정밀도 0.8에 필요한 특이도: 0.982 / 0.992
  판단: 모델 성향이 아니라 불균형 다중라벨 평가의 수학적 귀결이다.
        accuracy 단독 보고는 금물. 민감도·특이도·유병률을 함께 제시해야 한다.

[내부 프로브 — 위치 정보의 소재]
  P1 비전 타워(64x64 패치)          : 마커 16/16 위치 추적
  P2 projector 통과 후(16x16 토큰)  : 마커 16/16, 평균 위치 오차 0.069 이미지폭
  P3 병변 삽입 쌍대 검증            : 대조 255/160/90 -> 6/6, 오차 0.042
                                      대조 50(저대조) -> 6/6, 오차 0.051
  기준: 3x3 격자 한 칸 폭 = 0.333
  판단: 언어 모델이 받는 256토큰 격자에 위치 정보가 필요량의 5~7배 정밀도로 남아 있다.
        따라서 위치 관련 실패는 지각·인코딩·투영 단계의 문제가 아니라
        **출력(언어화) 단계의 문제**다.

  P4 선형 readout (leave-one-base-image-out, lam=1000)
      x: r=+0.653 MAE 0.178 / y: r=+0.495 MAE 0.181 (평균 예측 MAE 0.180)
  판단: 처음 보는 해부구조에서도 상관은 뚜렷한 양(+)이라 위치가 선형으로 디코딩
        가능함을 시사하지만, MAE가 평균 예측과 동일해 아직 실용 정확도는 아니다.
        단 이 특징은 토큰당 2560차원을 L2 노름 하나로 뭉갠 조악한 것이라
        디코딩 가능성의 **하한**으로 봐야 한다.


================================================================================
11. 해결책 적용과 검증
================================================================================
앞선 한계들을 실제로 고칠 수 있는지 해법 6종을 구현해 검증했다.
결과: 위치 추정 해법 5종은 전부 실패, 분류 해법 1종은 성공.

--------------------------------------------------------------------------------
[출발점이 된 논리 사슬]
--------------------------------------------------------------------------------
이 프로젝트의 측정 세 가지가 해법의 전제였다.
  (a) 위치 정보는 LM이 받는 256토큰에 정밀하게 존재한다
      (마커 16/16 오차 0.069, 삽입 병변 6/6 오차 0.042~0.051)
  (b) 텍스트 박스 채널은 그 정보를 못 내보낸다
  (c) 자연어로 물으면 좌우 75%가 나온다 (p=0.011)
  => "정보는 있는데 출력 경로가 막혔다"면 경로를 바꾸거나 보정하면 된다.
     이 가설을 5가지 독립 경로로 검증했다.

--------------------------------------------------------------------------------
[선행 진단 1] 박스 크기 보정 문제인가?  — 추론 없는 순수 측정
--------------------------------------------------------------------------------
검증 방식: 공식 형식으로 얻은 박스의 면적을 정답 박스 면적과 직접 비교.
  VinDr 병변      예측 중앙값 0.1037 vs 정답 0.0124  -> 8.3배
  DeepLesion CT   0.0168 vs 0.0028                  -> 5.9배
  BraTS 종양      0.1518 vs 0.0497                  -> 3.1배
  합성 마커       0.1205 vs 0.0324                  -> 3.7배
함의: 예측이 정답을 완벽히 포함한다고 가정해도 IoU 상한이 0.120 / 0.169 /
      0.327 / 0.269에 불과하다. 낮은 IoU의 상당 부분이 크기 과대예측에서 온다.

--------------------------------------------------------------------------------
[해법 1] 박스 사후 축소 — 실패
--------------------------------------------------------------------------------
발상: 중심이 맞고 크기만 크다면, 중심 기준으로 축소하는 것만으로 IoU가 올라야 한다.
검증 방식: 추론 없이 후처리만. 축소계수 k를 1.0 -> 0.2로 스윕하며 IoU 재계산.
           (중심이 맞는지 틀렸는지를 가르는 결정적 실험. 추가 비용 0.)
결과:
  VinDr      k=1.00 0.071 -> 최적 k=0.8에서 0.074  (1.03배)
  DeepLesion k=1.00 0.007 -> 최적 k=0.8에서 0.008  (1.15배)
  BraTS      k=1.00 0.229 -> 최적 k=1.0            (개선 없음)
  전 데이터셋에서 k<0.6부터는 오히려 악화
판정: 축소가 듣지 않는다 = **중심 자체가 틀렸다**. 크기 보정 문제가 아니다.

--------------------------------------------------------------------------------
[선행 진단 2] 중심은 얼마나 맞는가?  — 무지성 기준선과 대조
--------------------------------------------------------------------------------
검증 방식: 예측 박스 중심과 정답 중심의 거리를, "항상 영상 정중앙(0.5,0.5)을
           찍는" 기준선과 비교. 기준선을 못 이기면 위치 정보가 없다는 뜻.
결과 (중심오차, 낮을수록 좋음):
  VinDr       모델 0.245  vs 기준선 0.265   기준선 대비 승 22/37 = 59%
  DeepLesion  모델 0.245  vs 기준선 0.226   8/20 = 40%  (기준선보다 나쁨)
  BraTS       모델 0.180  vs 기준선 0.188   10/20 = 50% (우연)
  Cardiomegaly 직접질의 0.165 vs 기준선 0.135          (기준선보다 나쁨)
판정: 병변 박스의 중심은 정중앙 찍기와 사실상 동급이다.
      이로써 해법 2(coarse-to-fine)는 시도 전에 기각된다 — 1단계 영역이
      무정보이므로 그 영역으로 확대하면 병변을 잘라낼 위험만 커진다.

--------------------------------------------------------------------------------
[해법 2] Coarse-to-fine 크롭 재검출 — 기각 (선행 진단으로 전제 붕괴)
--------------------------------------------------------------------------------
발상: 1단계에서 영역을 잡고 거기로 확대한 뒤 재검출하면, 같은 상대 크기의 박스가
      절대적으로는 더 정밀해진다.
기각 사유: 위 선행 진단 2에서 1단계 중심이 무정보임이 확인됨. 전제가 성립하지 않음.

--------------------------------------------------------------------------------
[해법 3] 어텐션 읽기 — 실패 (대조군으로 확정)
--------------------------------------------------------------------------------
발상: 텍스트 채널을 우회해, 모델이 16x16 이미지 토큰 격자에서 어디를 보는지 직접 읽는다.
검증 방식:
  - 이미지 + "Is there {소견} in this image?"를 output_attentions=True로 순전파
  - 입력에서 이미지 토큰 구간을 image_token_id로 특정
  - 답변을 생성할 마지막 위치에서 이미지 토큰으로 가는 어텐션을 헤드 평균
  - 층을 early/mid/late 세 구간으로 나눠 각각 16x16 맵 -> peak와 centroid
  - **대조군**: 같은 이미지에 "What is the capital city of France?"라는
    완전히 무관한 질문으로 동일 절차 수행
결과:
  peak 오차가 관련 질문과 무관 질문에서 **완전히 동일** (0.588 / 0.555 / 0.575)
  centroid도 거의 동일 (예: VinDr early 0.293 vs 대조군 0.293)
  정중앙 기준선(0.265)도 못 넘음
판정: 어텐션 맵에 질문별 공간 정보가 없다. raw 어텐션은 attention sink에
      지배되는 것으로 알려져 있고 그 예상과 일치한다.

--------------------------------------------------------------------------------
[해법 4] 그래디언트 saliency — 약한 신호, 실용 불가
--------------------------------------------------------------------------------
발상: 어텐션은 '어디를 보는가'의 약한 대리지표다. 답변이 실제로 무엇에 **의존하는지**
      는 그래디언트가 직접 측정한다.
검증 방식:
  - 비전타워 -> projector로 256토큰 특징을 만들고 requires_grad 설정
  - 텍스트 임베딩에 이 특징을 끼워 넣어 inputs_embeds 구성 (이미지 토큰 위치에 주입)
  - "Yes" 토큰의 logit을 목표로 역전파
  - 토큰별 saliency 두 종류: grad의 L2 노름(gnorm), |grad·activation|(gxa)
  - 16x16으로 재구성해 peak / centroid
  - 대조군은 해법 3과 동일한 무관 질문
결과:
  관련 질문이 무관 질문보다 **일관되게 우수** (예: VinDr gxa peak 0.377 vs 0.507)
  -> 어텐션과 달리 질문별 공간 정보가 실재함
  그러나 절대 성능은:
    VinDr      gxa centroid 0.228  vs 정중앙 기준선 0.265   25/37 승, 부호검정 p=0.0235 (유의)
    DeepLesion gxa centroid 0.245  vs 기준선 0.226          (기준선보다 나쁨)
    BraTS      gxa centroid 0.220  vs 기준선 0.187          (기준선보다 나쁨)
  교란 점검: 예측 centroid 표준편차 (0.096, 0.069) vs 정답 표준편차 (0.211, 0.182)
            -> 예측이 중앙 근처로 수축돼 있음
  추적 여부 직접 확인: 예측-정답 상관 x r=+0.367, y r=+0.252 (양의 상관 존재)
판정: 신호는 진짜지만(상관 양수, 유의한 승률) 크게 수축돼 있고,
      3개 중 1개 데이터셋에서만 기준선을 넘는다. 실용 수준이 아니다.

--------------------------------------------------------------------------------
[해법 5] 역수축 보정 — 부분적, 불안정
--------------------------------------------------------------------------------
발상: 해법 4의 예측은 방향은 맞고 진폭만 눌린 수축 추정치다. 선형 보정으로 진폭을
      복원하면 오차가 줄어야 한다.
검증 방식: 축별 선형 회귀로 보정하되, 순환논리를 피하려고
           **leave-one-out**으로 적합(자기 자신은 학습에서 제외).
결과:
  VinDr      기준선 0.284 / 보정전 0.258 / 보정후 0.253   24/37 승, p=0.0494 (경계)
             기준선 대비 +11.1%
  DeepLesion 기준선 0.226 / 보정전 0.245 / 보정후 0.279   0/10 승  (-23.5%)
  BraTS      기준선 0.187 / 보정전 0.220 / 보정후 0.198   4/10 승  (-5.6%)
판정: 한 데이터셋에서만 경계 수준의 개선. 나머지는 악화. 일반화되지 않는다.

--------------------------------------------------------------------------------
[해법 6] 로그확률 기반 분류 — 성공
--------------------------------------------------------------------------------
공략 대상: 7장의 낮은 정밀도(CheXpert .267 / NIH .167).
           10장에서 이것이 유병률의 수학적 귀결임을 확인했고, 정밀도 0.8에는
           특이도 0.982~0.992가 필요하다는 계산이 나왔다. 그런데 yes/no를
           디코딩하면 작동점이 하나로 고정되어 특이도를 올릴 방법이 없다.
발상: 모델은 이미 답변 토큰의 분포를 계산한다. 생성된 단어 대신
        s = logP(yes) - logP(no)
      를 읽으면 (이미지,라벨)마다 연속 점수가 나오고, 임계값을 고를 수 있다.
검증 방식:
  - 프롬프트는 기존 방식 B와 동일. 첫 답변 토큰 위치의 logits에서 점수 계산
    ("Yes","yes"," Yes" / "No","no"," No" 변형을 logsumexp로 묶음)
  - uncertain 라벨 제외, 총 273건 (CheXpert 133, NIH 140)
  - **AUC**로 임계값과 무관한 변별력을 먼저 확인
    (AUC가 0.5면 어떤 임계값도 소용없다는 뜻이므로 이것이 1차 관문)
  - AUC 유의성은 **라벨 셔플 순열검정 10,000회**로 귀무분포를 직접 만들어 검정
  - 작동점은 **leave-one-IMAGE-out**으로 임계값을 골라, 자신이 포함되지 않은
    데이터로 정한 임계값에서만 채점 (같은 표본에 적합한 상한값과 분리해 보고)
결과:
  CheXpert  AUC 0.700  순열 귀무 95%구간 [0.347,0.650]  p=0.0043 (유의)
            기존 greedy : 정밀도 .242 재현율 .500 F1 .327 특이도 .786
            LOO 임계값  : 정밀도 .243 재현율 .562 F1 .340 특이도 .761
  NIH       AUC 0.673  순열 귀무 95%구간 [0.337,0.663]  p=0.0183 (유의)
            기존 greedy : 정밀도 .160 재현율 .308 F1 .211 특이도 .835
            LOO 임계값  : 정밀도 1.000 재현율 .154 F1 .267 특이도 1.000
  특이도 0.99 지점 점검:
            NIH      정밀도 .500 재현율 .231 (기존 .160에서 회복)
            CheXpert 정밀도 .000            (회복 실패)
판정: **AUC가 유의하게 0.5를 넘는다 = 변별 신호가 실재하며 greedy 디코딩이
      그것을 버리고 있었다.** 이것이 이 해법의 견고한 성과다.
      다만 특정 작동점 수치(정밀도 1.000 등)는 양성이 13~16건뿐이라 불안정하며,
      특이도를 끌어올렸을 때 NIH는 회복되지만 CheXpert는 실패하므로
      "기저율 이론대로 정밀도가 회복된다"고 일반화해서는 안 된다.
실무 권고: 이진 판정기가 아니라 **순위 매기기(triage) 도구**로 쓸 것.
           점수로 정렬해 상위를 우선 검토하는 용도가 AUC 0.67~0.70에 맞는 사용법이다.

--------------------------------------------------------------------------------
[종합 판정]
--------------------------------------------------------------------------------
  해법                      결과        기준선 대비            판정
  1 박스 사후 축소          1.03~1.15배  개선 없음             실패
  2 coarse-to-fine          —            전제 붕괴로 기각      기각
  3 어텐션 읽기             대조군과 동일 기준선 미달           실패
  4 그래디언트 saliency     상관 r=+0.37 1/3 데이터셋만 초과    약한 신호
  5 역수축 보정             VinDr +11%   나머지는 악화          부분/불안정
  6 로그확률 분류           AUC .70/.67  유의 (p=.004/.018)    성공

  위치 추정: 서로 다른 5가지 경로를 모두 막았다. 추론 단계 개입으로는 해결되지 않는다.
             이는 "파인튜닝이 필요하다"는 처방의 근거를 '이론적 추론'에서
             '5종 시도 실패'라는 실증으로 격상시킨다.
  분류     : 지금 당장, 모델 변경 없이 개선 가능하다.

  해법 4의 의미를 정확히 하면 — 그래디언트는 질문별로 다른 곳을 가리키므로
  모델이 병변 질문에 답할 때 위치 정보를 **아주 약하게는 사용한다**.
  다만 쓸 만한 수준으로는 사용하지 못한다. 이것이 10장 P1~P3(위치 정보는 토큰에
  정밀하게 존재)과 8장(텍스트 출력은 무정보) 사이의 간극을 메우는 관찰이다.

12. 한계와 처방
================================================================================
┌─ 한계 1 : 위치 추정이 학습 범주 밖으로 전이되지 않음 ────────────────────┐
  현상: 흉부 X-ray 해부구조 IoU 0.256(공식 0.380)로 작동하나,
        병변 박스 0.071 / CT 병변 0.007 / 비해부학적 표적 0.015로 붕괴.
  해석: 능력 부재가 아니라 학습 대상(ChestImaGenome 해부구조) 범위의 문제.
  추가 확인 (11장): 병변 박스의 중심은 '항상 정중앙 찍기'와 동급이다
        (VinDr 0.245 vs 0.265, DeepLesion 0.245 vs 0.226으로 오히려 나쁨).
        즉 크기만 틀린 것이 아니라 위치 자체가 무정보에 가깝다.
  해결:
    (즉시) 질의 대상을 학습 분포 안의 해부 명칭으로 잡을 것
           ("heart", "right lung", "cardiac silhouette"; "the main lesion" 같은
            모호한 대상은 피할 것)
    (효과 없음 — 11장에서 실증) 박스 축소 보정, coarse-to-fine 크롭,
           어텐션 읽기, 그래디언트 saliency, 역수축 보정.
           5종 모두 기준선을 유의미하게 넘지 못했다. 추론 단계 개입은 답이 아니다.
    (권장) 병변 위치가 목표면 파인튜닝. 이미 detect 출력 형식과 기본 능력이
           갖춰져 있고 내부 특징에 위치가 보존돼 있으므로 해부->병변 전이 학습의
           난이도는 낮을 것으로 판단(단, 파인튜닝 자체는 여전히 미검증 — 13장 참조).
           보유 데이터로 즉시 착수 가능: VinDr-CXR(박스), DeepLesion(박스),
           BraTS(마스크->박스) + 병변 삽입 합성 데이터.
    (대안) 전용 검출기가 위치를 잡고 MedGemma가 해당 영역을 서술하는 역할 분담.
           파인튜닝 없이 오늘 구현 가능하며 강점(소견 서술)은 유지된다.

┌─ 한계 2 : 프롬프트 형식에 극도로 민감 ───────────────────────────────────┐
  현상: 비공식 출력 형식을 요구하면 영상과 무관한 상수로 퇴화
        (셀 "5" 26/30, 숫자 "0.5" 32/32, 축대칭 템플릿 박스 80%,
         이분 선택은 첫 선택지 편향).
  해석: 모델 카드도 "Gemma 3보다 프롬프트에 민감"하다고 경고한 특성.
  해결: 공식 형식을 그대로 쓸 것. 위치는 형식 B, 3D는 형식 C (5장).
        좌표 파싱 시 [y0,x0,y1,x1] / 0~1000 스케일 주의.
        자체 형식을 쓰기 전에 반드시 기하가 알려진 대상으로 규약을 검증할 것.

┌─ 한계 3 : CT/MRI 단일 슬라이스 입력 시 신뢰성 붕괴 ──────────────────────┐
  현상: CT 단면 1장 -> 모달리티를 "Chest X-ray"로 오인하고 그 위에 판독문 생성.
        MR 단면 1장 -> 종양 유형 0/12(포괄어·오진), 시퀀스마다 병변 위치가 바뀜.
  해결: 공식 3D 다중 슬라이스 형식 사용. 적용 시 CT 모달리티 3/3,
        MR 종양 유형 3/3, 병변 위치 일관.
        CT는 HU 3중 윈도우 RGB 인코딩이 필수이므로 **HU가 보존된 원본**이 필요하다.
        이미 8bit로 윈도잉된 PNG(예: DeepLesion)로는 공식 전처리를 적용할 수 없다.

┌─ 한계 4 : 거짓 전제에 반박하지 않음 ─────────────────────────────────────┐
  현상: 무내용 영상에 "흉부 X-ray 소견을 기술하라"고 하면 상세히 날조.
        같은 영상에 중립 질문을 하면 "Noise"라고 정확히 답함.
  해결: 모든 소견 기술 프롬프트에 "해당하지 않으면 그렇다고 명시하라"는
        탈출구를 넣을 것. 검증 결과 환각이 사라짐. 비용 0.
        존재를 전제하는 질문("~가 보이나?")은 위양성을 유발하므로 주의.

┌─ 한계 아님 : 다중라벨 정밀도 저하 ───────────────────────────────────────┐
  유병률 10~12%·특이도 0.81이면 정밀도 0.27은 수학적 필연 (예측=실측 일치).
  평가 설계 문제이지 모델 결함이 아니다. accuracy 단독 보고 금지.
  해결 (11장 해법 6에서 검증됨): greedy yes/no 대신
        s = logP(yes) - logP(no) 를 점수로 사용할 것.
        AUC 0.700(CheXpert) / 0.673(NIH), 순열검정 p=0.0043 / 0.0183로 유의.
        즉 변별 신호가 실재하며 greedy 디코딩이 그것을 버리고 있었다.
        용법: 이진 판정기가 아니라 순위 매기기(triage) 도구로 쓸 것.
        주의: 특정 작동점 수치는 양성 13~16건이라 불안정하다.

13. 근거 강도 구분과 방법론 교훈
================================================================================
[강하게 증명됨 — 통제 실험 / 쌍대 비교 / 공식 수치 대조]
  - 공식 형식에서 해부구조 위치 추정이 작동 (IoU 0.256~0.313)
  - 학습 범주 밖(병변·CT·합성표적)으로 전이되지 않음
  - 3D 입력이 CT 모달리티 인식과 MR 종양 유형 명명을 결정적으로 개선
    (CT 2/3->3/3, MR 0/12->3/3; 같은 볼륨·같은 질문, 입력 방식만 변경)
  - 비공식 형식에서의 상수 출력 퇴화 (무내용 영상에서도 동일 출력 = 영상 의존성 0)
  - 긍정 편향 없음 (있을 수 없는 소견 0/30)
  - 낮은 정밀도는 기저율 귀결 (공식 예측=실측)
  - 전제를 주면 환각, 중립적으로 물으면 정확 (동일 영상 대조)
  - 가드 문구가 환각을 제거
  - 위치 정보가 LM 입력단 256토큰까지 정밀 보존 (오차 0.069, 저대조 병변도 0.051)
  - 평가 파이프라인 타당성: SLAKE F1 61.1 vs 공식 59.7 (n=82)
  - 병변 박스 중심이 '정중앙 찍기' 기준선과 동급 (무지성 기준선 대조)
  - 어텐션 맵에 질문별 공간 정보 없음 (무관 질문 대조군과 peak 완전 일치)
  - 추론 단계 위치 해법 5종이 모두 기준선을 넘지 못함 (11장)
  - 분류 점수의 변별력 (AUC .700/.673, 라벨 셔플 순열검정 p=.0043/.0183)

[통계적으로 유의하나 표본이 작음]
  - 자연어 유도 시 좌우 75%(18/24, p=0.011), 상하 76%(13/17, p=0.025)
  - 3분할은 우연 수준 (7/30) — 즉 유효 해상도는 축당 1비트

[통계적으로 유의하나 표본이 작거나 일반화되지 않음]
  - 그래디언트 saliency의 위치 신호: VinDr 25/37 p=0.0235, 상관 x r=+0.367,
    그러나 3개 데이터셋 중 1개에서만 기준선 초과
  - 역수축 보정: VinDr +11.1% p=0.0494(경계), 나머지 2개는 악화
  - 로그확률 분류의 특정 작동점(예: NIH 정밀도 1.000): 양성 13건 기준이라 불안정.
    견고한 주장은 AUC이며 작동점 수치가 아니다.

[추론이며 미검증 — 실측 필요]
  - "해부->병변 전이 파인튜닝이면 해결된다"
    지지 근거: 내부 특징에 위치 보존 + 이미 detect 형식/능력 보유
               + 추론 단계 해법 5종이 모두 실패해 학습 외 선택지가 소진됨(11장)
    반대 정황: 조악한 선형 readout은 상관 r=+0.65/+0.50이지만 MAE가 평균 예측과 동일.
    -> VinDr 박스로 소규모 LoRA를 실제로 돌려 IoU를 재야 확정된다.
  - BraTS 종양(0.229)이 다른 병변보다 높은 이유를 "덩어리라 해부구조 검출로
    환원되기 때문"으로 본 것은 해석이며 검증되지 않았다.

[일반화 금지 — 표본 한계]
  - 데이터셋당 10케이스(SLAKE만 QA 82개), CT 3D는 3케이스, MR 3D는 3케이스.
    벤치마크가 아니라 정성적 검증 규모다.
  - NIH 10장 중 7장이 Hernia, Kvasir 10장 전부 궤양성 대장염으로 편중.
  - CheXpert/NIH는 비공식 커뮤니티 미러.
  - 해부구조 위치추정 정답은 Chest ImaGenome 원본이 아니라 VinDr 박스 대리.
  - CT/MR 3D의 **소견 내용 정확도**는 검증하지 못함(병리 라벨·판독문 부재).
    모달리티 인식과 종양 유형처럼 정답이 있는 항목만 수치화했다.

[방법론 교훈]
  1. 모델 버전과 문서 버전을 반드시 대조할 것.
     초기에 1.5를 실행하면서 구버전 문서로 해석해 능력을 잘못 부정했다.
     사용자의 "공식 형식을 쓴 게 맞느냐"는 지적으로 발견했다.
  2. "할 수 없다"는 결론 전에 공식 사용법부터 확인할 것.
     공식 detect 형식·3D 형식 적용만으로 여러 '한계'가 사라지거나 크게 완화됐다.
  3. 형식을 추측하지 말고 실측할 것.
     공식 노트북을 직접 내려받아 코드 셀에서 전처리를 추출했고,
     좌표 규약은 좌/우 폐처럼 기하가 알려진 대상으로 검증했다.
  4. 모든 지표에 무지성 기준선을 병기할 것.
     격자 정확도 0.4~0.5는 '항상 중앙'(0.4~0.6)보다 낮았는데, 기준선이 없었다면
     성능이 있는 것으로 오독할 수치였다.
  5. max_new_tokens를 넉넉히(>=64) 잡을 것.
     서두를 쓰다 잘린 답변을 '파싱 실패'로 집계해 가짜 실패를 두 번 만들었다.
  6. 커뮤니티 미러는 features 스키마로 라벨 규약을 먼저 확인할 것.
     CheXpert의 0=unlabeled/1=uncertain/2=absent/3=present를 오독한 적이 있다.
  7. 정답 라벨의 의미를 프롬프트와 맞출 것.
     DeepLesion의 lesion_type은 진단명이 아니라 부위명인데 진단명을 물어
     지표가 엉뚱한 것을 측정했다.
  8. 해석 기법(어텐션·saliency)에는 반드시 **무관 질문 대조군**을 둘 것.
     어텐션 맵은 그럴듯해 보였지만 "프랑스 수도는?"과 동일했다. 대조군이 없었다면
     위치 추정에 성공했다고 오판했을 것이다.
  9. 보정·적합을 할 때는 leave-one-out으로 순환논리를 차단할 것.
     역수축 보정과 로그확률 임계값 모두, 같은 표본에 적합한 상한값과
     LOO로 정직하게 추정한 값을 함께 보고했다 (상한과 실제의 차이가 컸다).
 10. 임계값에 의존하는 지표 이전에 AUC 같은 임계값 무관 지표를 먼저 볼 것.
     AUC가 0.5면 어떤 임계값도 소용없으므로 이것이 1차 관문이 된다.

15. 미해결 항목
================================================================================
1. 해부->병변 전이 파인튜닝 (최우선)
   VinDr-CXR 박스로 소규모 LoRA를 돌려 IoU를 측정. 12장에서 유일하게 미검증인
   핵심 주장을 확정하거나 반증한다. 공식 detect 출력 형식을 그대로 학습 타깃으로
   쓰면 되므로 구현 부담이 적다.

2. Chest ImaGenome 정답으로 공식 벤치마크 재현
   PhysioNet 자격증명을 얻으면 대리 정답이 아닌 원본으로 0.380 재현 여부를 확인할 수 있다.

3. CT/MR 3D 소견의 임상 정확도 평가
   현재는 모달리티·종양유형만 정답 대조가 가능했다. 판독문이 딸린 3D 데이터
   (예: CT-RATE)를 쓰면 소견 서술 자체를 정량 평가할 수 있다.

4. 3D 슬라이스 수의 영향
   85장은 공식 상한을 그대로 쓴 값이다. 슬라이스 수를 줄여가며 성능-비용 곡선을
   그리면 실제 운용 설정을 정할 수 있다.

5. 표본 확대
   현재 결론은 데이터셋당 10케이스(3D는 3케이스) 규모다. test split 전체로
   확장해 결론이 유지되는지 확인해야 논문급 수치가 된다.

6. hf_cache 모델 중복 8.1GB x 2 정리 (사용자 확인 필요)
