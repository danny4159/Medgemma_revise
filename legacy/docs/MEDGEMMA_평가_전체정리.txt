본 문서 8~12장의 핵심 결론 하나가 **틀렸다**. 사용자의 지적("1.5 공식 위치 추정
예제와 입출력 형식을 쓴 게 맞느냐")으로 발견했고, 재검증해 정정했다.

[무엇이 틀렸나]
  나는 "MedGemma에는 검출/grounding 학습이 없고 <loc> 토큰도 없으므로 좌표 출력
  경로가 아예 없다"고 결론지었다. 근거는 MedGemma **1** 기술보고서(arXiv:2507.05201).
  그러나 실제 사용 모델은 **MedGemma 1.5**였고, 1.5는 바로 그 기능을 추가한 버전이다.

  모델 카드(로컬 hf_cache 내 README.md) 공식 수치 — Chest ImaGenome 해부구조 bbox IoU:
      Gemma 3 4B  5.7  |  MedGemma 1 4B  3.1  |  MedGemma 1.5 4B  38.0  |  MedGemma 1 27B  16.0
  즉 "위치를 못 말한다"는 MedGemma 1에 대해서는 사실이었고(3.1), 1.5에서 38.0으로 도약했다.

  1.5 신규 기능(모델 카드 명시):
    - Anatomical localization: 흉부 X-ray의 해부구조/소견 bounding box 위치 추정
    - 3D CT/MRI 볼륨 해석
    - Whole-slide histopathology
    - Longitudinal(과거 영상 대비) 해석
    - 의료 문서/EHR 이해
  학습 데이터에 ChestImaGenome(MIMIC-CXR 해부구조 박스 세트)가 포함됨.

[형식도 틀렸다]
                    내가 쓴 것                          공식(모델 탐색으로 확인)
  프롬프트   "give bbox as [x_min,y_min,x_max,y_max]"   Detect the {obj}. Output a JSON
                                                        list ... "box_2d" ... "label".
  좌표 순서  x 먼저                                     y 먼저 [y0, x0, y1, x1]
  스케일     0~1                                        0~1000
  출력       평문 숫자                                  ```json [{"box_2d":[...],"label":...}]```

  좌표 규약 검증 방법: 같은 흉부 X-ray에서 "right lung"과 "left lung"을 각각 검출시켜
  3장 모두 우폐 박스가 좌폐 박스보다 영상 왼쪽에 위치함을 확인(방사선학적 관례와 일치).

[공식 형식으로 재측정한 결과]
  대상                       평균 IoU   비고
  심장(해부구조)              0.313     최대 0.542, 4건 중 2건이 IoU>=0.3
  해부구조 전체               0.256     공식 Chest ImaGenome 0.380과 같은 범주
                                        (정답이 VinDr 심비대 박스 대리라 과소평가됨)
  BraTS 뇌종양                0.229     내 임의 형식에서는 0.108 — 두 배 개선
  VinDr 병변 클래스별         0.071     내 임의 형식 0.128
  DeepLesion CT 병변          0.007     사실상 0
  합성 흰 원 마커             0.015     사실상 0

[정정된 결론]
  MedGemma 1.5는 위치 추정 능력이 **있다**. 단 학습한 범주에 한정된다.
    - 흉부 X-ray '해부구조'      : 작동함 (IoU 0.26~0.31, 공식 0.38)
    - 뇌 MRI 종양                : 부분 작동 (0.229)
    - 흉부 X-ray '병변' 박스     : 거의 안 됨 (0.071)
    - CT 병변                    : 안 됨 (0.007)
    - 비해부학적 합성 표적       : 안 됨 (0.015)
  즉 한계는 "위치를 못 본다"가 아니라
  **"학습한 범주(흉부 X-ray 해부구조) 밖으로 일반화되지 않는다"** 이다.

[본문 중 여전히 유효한 것 / 무효인 것]
  유효: 9-1(bbox 템플릿), 9-3(전제 순응 환각), 9-4(긍정 편향 반증), 9-5(기저율),
        9-6/9-7(자연어 유도 시 좌우 75%), 9-8(인코더/projector에 위치 정보 보존),
        10장 R4(가드 성공), 7장(내 구현 버그들)
        — 이들은 형식과 무관하게 관측된 사실이거나 내부 프로브 결과다.
  무효: 8~11장에서 "좌표 출력 경로가 아예 없다", "학습에 검출 태스크가 없다",
        "<loc> 토큰이 없어 불가능하다", "프롬프트로는 절대 안 된다"는 취지의 서술 전부.
        특히 11장 한계 1의 진단과 처방은 아래로 대체한다.
  주의: 9-1의 축대칭 템플릿([0,0,1,1] 등)은 **잘못된 형식으로 물었을 때의 반응**이었다.
        공식 형식에서는 박스가 영상에 따라 달라지고 해부학적으로 타당하다.

[대체된 처방 — 11장 한계 1을 이것으로 갈음]
  1) 위치가 필요하면 반드시 공식 detect 형식을 쓸 것:
       Detect the {obj}. Output a JSON list where each entry contains the 2D
       bounding box in "box_2d" and a text label in "label".
     파싱 시 [y0,x0,y1,x1] / 0~1000 스케일임에 주의(내가 처음 틀린 지점).
  2) 질의 대상을 '해부구조'로 잡을 것. "the main lesion" 같은 모호한 대상이 아니라
     "heart", "right lung", "cardiac silhouette" 등 학습 분포 내 명칭.
  3) 병변 위치가 목표라면 파인튜닝이 여전히 필요. 단 근거가 달라졌다 —
     "능력이 없어서"가 아니라 "해부구조에서 병변으로 전이가 안 되어서"이며,
     이미 해부 박스 출력 형식과 능력이 있으므로 전이 학습 난이도는 더 낮다.
  4) CT는 별도 재검증 필요(아래 미해결 항목 참조).

[아직 해결 못 한 것 — CT 결론 보류]
  1.5는 CT/MRI를 **3D 볼륨**으로 받는 기능이 있는데, 나는 2D 단면 한 장씩만 넣었다.
  따라서 6장·9장·11장의 "CT를 chest X-ray로 오인한다"는 결론은 입력 방식이
  공식 사용법과 달랐을 가능성이 있어 **보류**한다. 확정하려면 모델 카드가 안내하는
  CT 노트북의 공식 입력 형식으로 재실험해야 한다. (형식을 또 추측해서는 안 된다 —
  이번 오류의 원인이 정확히 그것이었다.)

[요청 1] "medgemma 현재 서버 GPU로 실행할 수 있을 만큼 세팅 돼 있어?"
  → nvidia-smi, conda env 목록, 패키지 버전, 모델 캐시, HF 토큰을 각각 확인.
    결론: 실행 가능. 단 기본 python3(anaconda base)에는 torch가 없고,
    별도 conda env `medgemma`에 모든 것이 설치돼 있음을 확인해 안내.

[요청 2] "실험해볼 만한 데이터셋도 있나?"
  → 로컬 /SSD1_1TB/.../Dataset 탐색. IXI 뇌 MRI(T1/T2/PD/MRA)만 존재하는데
    텍스트 리포트나 QA 페어가 없어 MedGemma(이미지+텍스트)용으로 부적합 판정.
    공개 데이터셋 후보를 제시.

[요청 3] "추천한 데이터셋들이 실제 MedGemma 학습에 쓰인 것들인가?"
  → 추측하지 않고 arXiv:2507.05201 원문을 WebFetch로 조회해 Table 1 확인.
    내가 앞서 추천한 VQA-RAD, SLAKE가 실제로는 학습에 포함돼 있었음을 확인하고
    정정. PathVQA는 품질 문제로 학습에서 의도적으로 제외됐다는 사실도 확인.

[요청 4] "학습에 안 쓰인 것 중 평가하기 좋은 데이터셋은?"
  → Table 1 전체를 재조회해 학습 포함 목록을 확정(PAD-UFES-20도 학습에 포함).
    학습 미포함으로 명시된 ChestX-ray14, CheXpert와,
    학습 목록에 아예 없는 모달리티(내시경, 유방촬영, 뇌 MRI)를 구분해 제시.

[요청 5] "다운받자. 10명 정도씩만. 학습 포함/미포함 둘 다."
  → HF 접근 가능성을 먼저 개별 테스트한 뒤 5개 데이터셋 × 10장 다운로드.
    전체 다운로드를 피하려고 SLAKE는 212MB zip 전체가 아니라
    remotezip으로 필요한 10장만 부분 추출.

[요청 6] "어떤 데이터셋을 얼마나 받았는지 / 정리해줘"
  → 이미지 shape, 포맷, 라벨 형태를 직접 읽어 표로 정리.
    이 과정에서 CheXpert 라벨 인코딩이 수상하다는 점을 스스로 발견해 플래그.

[요청 7] "X-ray 중에 BraTS/DeepLesion처럼 병변 위치가 라벨된 건 없나?"
  → 맞다고 인정(기존 X-ray 3종은 전부 위치 라벨 없음).
    VinDr-CXR 추가 확보 (방사선의 판독 bounding box, 22종 병변).

[요청 8] "MedGemma는 X-ray/MR/CT가 동시에 학습된 건가, weight가 따로인가?"
  → 논문 재조회. 단일 SigLIP 인코더 + 단일 Gemma 3 디코더, 모달리티별 분기 없음,
    혼합 데이터 동시 학습임을 확인해 답변.

[요청 9] "이 데이터셋들로 MedGemma를 평가하려면 어떻게? 이미지만 넣으면 텍스트가
          나오는 형태인데, 텍스트 라벨이 없는 데이터셋은 어떻게 평가하나?"
  → 라벨 형태 기준으로 3그룹으로 나누고 그룹별 평가 전략 설계·제안.

[요청 10] "그룹 3은 좌우상하 말고 bbox나 pixel 위치를 뽑아낼 수 없나?"
  → 추측 대신 검증. Gemma 3에는 PaliGemma의 <loc> 좌표 토큰이 없고
    MedGemma 논문에 grounding/localization 언급이 전무함을 확인.
    "숫자는 뱉지만 신뢰할 수 없다"고 답하고 3가지 측정 방식을 제안.

[요청 11] "그룹 1,2,3 전부 평가해라. 그룹2는 A,B,C 다, 그룹3은 3가지 방식 다,
           병변 명칭도 확인. inference 다 돌리고 결과 정리."
  → 542 태스크 설계 → 추론 → 채점 → 보고. (5~7장)

[요청 12] "잘 안 된 것들의 원인을 검증과 추가 실험으로 규명해라."
  → 가설 수립 → 통제 실험 설계 → 실행 → 일부 가설 반증, 일부 확증. (8~9장)

[요청 13] "모델 자체의 어떤 한계인가? 해결하려면 뭘 바꿔야 하나? 애매하면 검증해라."

3. MedGemma 모델 자체에 대한 사실 확인
================================================================================
[!! 경고 !!] 이 장은 MedGemma **1** 기술보고서를 근거로 작성됐다. 실제 사용 모델은
             MedGemma **1.5**이며 1.5에서 달라진 부분은 문서 맨 앞 '중대 정정'을 볼 것.
             특히 아래 "검출/grounding 태스크가 전혀 없음"은 1.5에는 해당하지 않는다.

출처: MedGemma Technical Report (arXiv:2507.05201), WebFetch로 직접 조회

[구조]
  - 비전 인코더: SigLIP 400M 단일 인코더. X-ray/CT/MRI/피부/병리/안저 전부
    동일한 weight로 처리. 모달리티별 expert나 별도 체크포인트 없음.
  - 언어 모델: Gemma 3 디코더 (4B / 27B). 모달리티별 분기 없음.
  - 학습 방식: 인코더를 여러 모달리티 의료 데이터 혼합으로 파인튜닝 →
    멀티모달 프리트레이닝 → distillation/RL. 전 단계에서 모달리티 혼합.
  - 입력: 2D 이미지만. 논문 명시 — "3D volumes ... were not included."
    따라서 CT/MRI도 2D 슬라이스로 잘라 넣어야 함.

[학습에 포함된 데이터 (Table 1)]
  Radiology      : MIMIC-CXR 231,483 / VQA-RAD 1,391 / SLAKE 450 /
                   Digital Knee X-ray 1,469 / CT-US 59,979 / MRI-US 47,622
  Histopathology : internal 32,550,599
  Dermatology    : PAD-UFES-20 2,047 / internal 51,049
  Ophthalmology  : EyePACS 199,258

                   HealthSearchQA, 합성 데이터 200,000

[평가 전용 (학습 미포함)]
  ChestX-ray14(CXR14), CheXpert, MedXpertQA 등.
  PathVQA/MedVQA는 데이터 품질 문제로 학습에서 의도적으로 제거했다고 명시.

[중요] 학습 태스크에 검출(detection)/분할(segmentation)/grounding이 전혀 없음.
       논문 전체에 bounding box, localization, grounding, coordinates,
       <loc> 토큰 언급 없음. 평가 태스크도 분류/VQA/리포트 생성/이미지-텍스트

       토크나이저에 없음. 즉 좌표를 표현할 전용 어휘 자체가 없음.

5. 본 평가 설계와 추론 방식 (542 태스크)

[추론 메커니즘 — 공통]
  파이프라인: transformers pipeline("image-text-to-text")
  모델 로딩 : torch_dtype=bfloat16, device="cuda" (단일 GPU, 약 8GB 점유)
  입력 형식 : messages = [{"role":"user","content":[{"type":"image","image":PIL},
                                                    {"type":"text","text":prompt}]}]
  디코딩    : do_sample=False (greedy). 완전 결정적 — 같은 입력은 항상 같은 출력.
  출력 저장 : JSONL 한 줄에 {group, dataset, method, image, prompt, output, gt, error}
              매 쿼리마다 flush. 중단돼도 (dataset, method, image, prompt) 키로
              이어서 실행 가능한 resume 로직 내장.

[그룹 1] 자유서술형 QA가 이미 있는 데이터 — 102 태스크
  대상    : vqa_rad(10), slake(82 QA), kvasir_vqa(10)
  방식    : meta.json의 question을 그대로 프롬프트로 사용.
            정답이 한 단어~짧은 구이므로 뒤에 다음 지시를 덧붙임:
            "Answer with a single word or a short phrase only, with no explanation."
            (이 지시 없이는 모델이 장황하게 답해 token F1이 부당하게 낮아짐.
             스모크 테스트에서 확인 후 추가한 조치)
  채점    : SQuAD식 정규화(소문자화, 구두점 제거, 관사 제거) 후
            - token F1: 예측/정답 토큰 겹침의 조화평균
            - exact match: 정규화 후 완전 일치
            - closed accuracy: 정답이 yes/no인 문항만 따로 집계

[그룹 2] 이미지 단위 분류 라벨만 있는 데이터 — 320 태스크
  대상    : chexpert(14 라벨), nih_chestxray14(14 라벨)
  방식 A (다중선택, 이미지당 1회 = 20태스크):
            "From the following list, select ALL findings visible in this chest
             X-ray: <14개 라벨 나열>. Respond with only a comma-separated list."
            채점: 출력에 등장한 라벨명을 예측 집합으로 보고 정답 present 집합과
                  micro precision/recall/F1
  방식 B (개별 yes/no, 이미지당 14회 = 280태스크):
            "Does this chest X-ray show <라벨>? Answer only yes or no."
            채점: 출력에서 첫 yes/no를 정규식으로 추출.
                  정답: 라벨이 present면 yes, absent면 no.
                  uncertain 라벨은 채점에서 제외(CheXpert 7건).
                  accuracy / sensitivity / specificity / precision + 혼동행렬
  방식 C (자유서술 후 키워드 매칭, 이미지당 1회 = 20태스크):
            "Describe the findings in this chest X-ray."
            채점: 라벨별 동의어 사전(예: Cardiomegaly -> "cardiomegaly",
                  "enlarged heart", "cardiac enlargement", "increased cardiac
                  silhouette" 등)으로 출력 텍스트를 매칭해 예측 집합 구성 후
                  A와 동일하게 micro P/R/F1

[그룹 3] 위치(박스/마스크) 라벨만 있는 데이터 — 120 태스크
  대상    : brats2023, deeplesion_ct, vindr_cxr (각 10장 × 4방식)
  정답 준비:
    - brats     : 저장해둔 이진 분할 마스크 PNG에서 전경의 최소/최대 좌표로
                  bounding box를 계산해 정규화
    - deeplesion: 정규화 xywh -> xyxy 변환
    - vindr     : 픽셀 xyxy를 orig_width/height로 나눠 정규화.
                  박스가 여럿이면 면적 최대 박스를 'main lesion'으로 지정.
    - 격자 정답 : 박스 중심점이 속하는 3x3 칸 번호(1~9)
  방식 1 (격자 분류):
            3x3 9칸의 번호 규칙을 프롬프트에 명시하고
            "Which single cell contains the main lesion? Respond with only the
             cell number." -> 정확도
  방식 2 (직접 bbox):
            "Give the bounding box ... as normalized coordinates
             [x_min,y_min,x_max,y_max] ... Respond with only the four numbers."
            -> 정규식으로 숫자 4개 추출해 정답 박스와 IoU.
               비교 기준으로 '전체 영상을 답했을 때의 IoU'도 함께 계산.
  방식 3 (자유서술 + 위치 키워드):
            "Describe the main abnormality: what it is and where it is located."
            -> 정답 박스 중심에서 좌/우/중앙, 상/중/하를 유도하고 출력 텍스트의
               위치어와 매칭. 중요: 방사선학적 관례(영상 왼쪽 = 환자 오른쪽)로
               채점한 것과 영상 좌표 그대로 채점한 것을 둘 다 계산해 비교.
  방식 4 (병변 명칭):
            "What is the single most likely lesion type or diagnosis visible?
             Respond with a short medical term only."
            -> 정답 명칭 동의어 사전으로 매칭

  증상: 격자 질문에서 deeplesion/vindr이 100% 파싱 실패로 집계됨.
  원인: max_new_tokens=8로 설정. 모델이 "Based on the image, the main lesion"
        이라는 서두를 쓰다가 숫자를 말하기 전에 잘림. 거부가 아니라 절삭.
  조치: 격자 8->64, 이진질문 32->64로 상향하고 해당 310건을 전부 재실행.
        원본은 eval_results/raw_outputs_v1_truncated.jsonl에 보존.
  교훈: "파싱 실패 100%"는 모델 거부가 아니라 측정 버그일 수 있음. 항상 원문 확인.
  (같은 실수를 뒤에서 한 번 더 반복함 — 후속 실험의 상하 질문 32토큰 절삭)

[결함 2] CheXpert 라벨 인코딩 오해 — 발견 후 수정
  증상: meta.json에 "No Finding": 3 같은 값이 그대로 들어가 있었음.
  실제: datasets의 ClassLabel 정의가 0=unlabeled, 1=uncertain, 2=absent, 3=present.
        내 최초 코드는 0만 걸러내고 2(absent)까지 '라벨 있음'으로 저장 — 명백한 오류.
  조치: fix_chexpert_meta.py로 present/absent/uncertain을 분리 저장하도록 재생성.
  교훈: 커뮤니티 미러는 원본 라벨 규약을 반드시 features 스키마로 확인해야 함.

[결함 3] DeepLesion 병변명 평가가 애초에 다른 것을 측정
  DeepLesion의 lesion_type은 진단명이 아니라 부위명(abdomen, bone, liver...).
  그런데 프롬프트는 "진단명"을 물었음. 그래서 모델이 "Renal cyst"라 답하면
  kidney 동의어에 걸려 정답, "Abscess"라 답하면(실제로 복부 병변인데도) 오답.
  -> 이 데이터셋의 name_accuracy 0.30은 그대로 해석하면 안 됨.

[결함 4] 기준선 없이 보면 성능이 있는 것처럼 오해할 수치
  격자 정확도 0.4~0.5는 얼핏 우연(1/9=0.11)보다 훨씬 좋아 보이지만,
  정답 위치가 중앙에 몰려 있어 '항상 5번'이라고만 답해도 0.4~0.6이 나옴.
  기준선을 같이 계산하지 않았다면 정반대 결론을 낼 뻔했음.

[결함 5] n=30 선형 프로브를 과해석할 뻔함
  실제 병변 30장에 256차원 특징으로 ridge 회귀 -> r은 0 근처, MAE는 평균 예측보다
  나쁨. 이는 '정보가 없다'는 증거가 아니라 표본 대비 차원이 과도해 프로브가
  무의미했던 것. 부재의 증거로 쓰지 않고 통제 실험(쌍대 비교)으로 대체함.


================================================================================
8. 원인 규명 실험 — 설계와 메커니즘
================================================================================
"왜 안 됐는가"를 가설 -> 통제 실험으로 검증.

[추론 없이 가능한 분석]
  A. bbox 출력의 분산 분석
     기존 30개 bbox 답변의 좌표값 분포를 직접 조사.
     "실제로 영상을 보고 추정했다면 x_min과 y_min이 우연히 같을 리 없다"는 착안.

  B. 기저율 수식 검증
     정밀도 = 민감도*유병률 / (민감도*유병률 + (1-특이도)*(1-유병률))
     관측된 민감도/특이도/유병률을 넣어 계산한 정밀도가 실측과 맞는지 확인.
     맞으면 '모델 편향'이 아니라 '유병률의 수학적 귀결'임이 증명됨.

  C. QA 실패 사례 육안 검토
     vqa_rad 10건, kvasir 10건을 전부 출력해 '모델 오류'인지 '내 채점 문제'인지 분류.

[E1] 합성 마커 통제 실험 — 공간 인식의 유무를 의료 난이도와 분리
  설계: 실제 의료 영상 4장(brats/deeplesion/vindr/chexpert)에
        지름이 영상 단변의 18%인 순백색 원(검은 테두리)을 4개 모서리 위치에 그림.
        총 16장. 눈으로 확인해 '절대 못 찾을 수 없는' 수준임을 검증함.
  질문: 격자 번호 / bbox / 좌우 절반 / 상하 절반
  논리: 의료 병변 판독이 어려워서 못 찾는 것인지, 위치 자체를 못 말하는 것인지 분리.

[E2] 무내용 영상 — 영상 의존성 자체를 테스트
  설계: (a) 균일한 회색 512x512, (b) 순수 난수 노이즈 512x512
  질문: 격자 / bbox / "이 흉부 X-ray의 소견을 기술하라" / "이 영상의 모달리티는?"
  논리: 영상에 아무 정보가 없는데도 확신에 찬 답이 나오면, 그 답은 영상이 아니라
        사전확률(prior)에서 온 것. 또 '전제를 준 질문'과 '중립 질문'을 비교하면
        환각이 지각 실패인지 전제 순응인지 구분됨.

[E3] 답변 편향 테스트
  설계: (a) 흉부 X-ray에 있을 수 없는 소견 3종(뇌종양/충치/대퇴골 골절)을 물음 x 10장
        (b) 부정형 표현 "Is this chest X-ray free of <소견>?" x 3라벨 x 10장
  논리: (a)에서 yes가 많이 나오면 무분별한 긍정 편향.
        (b)에서 답이 뒤집히면 표현 형태에 휘둘리는 것.

[E4] 모달리티 식별
  설계: CT 10장, MRI 10장, X-ray 10장에 대해
        (a) 4지선다 강제선택 (b) 개방형 "이 영상의 모달리티는?"
  논리: 선택지를 좁혀줘도 CT를 못 맞히는지 확인.

[E5] 빈 캔버스 마커 — 해부학 단서 제거
  배경: E1에서 상하만 12/16으로 높게 나옴. 흉부 X-ray는 상하로 해부학 구배가
        뚜렷(폐첨 vs 횡격막)하지만 좌우는 대칭에 가까움. 그래서 상하 성공이
        진짜 공간 인식인지, "횡격막 근처니까 아래"라는 해부학 추론인지 의심.
  설계: 해부학이 전혀 없는 균일 배경에 검은 원을 4위치에 그려 동일 질문.

[E6] 축별 변별력 확대 검증 (n=16)
  설계: 빈 캔버스 4x4 = 16위치에 마커. 좌우/상하 각각 16회.
  추가 통제:
    - 선택지 순서 뒤집기 ("RIGHT or LEFT", "BOTTOM or TOP") — 순서 편향 배제
    - 숫자 추정 ("0.00~1.00 사이 숫자로 답하라") — 이분 선택 자체를 제거
    - 순서 없는 빈칸 채우기 ("The marker is in the ___ half") — 선택지 미제시
  논리: 같은 능력을 4가지 다른 출력 형식으로 물어 형식 의존성을 분리.

[E7] 실제 병변에 빈칸 채우기 적용
  설계: 그룹 3의 30장 전부에 대해 순서 없는 빈칸 채우기로 좌우/상하를 물음.
        영상 좌표 기준과 방사선학적 관례 기준 양쪽으로 채점.

[모델 내부 프로브] 정보가 어느 단계에서 사라지는가
  P1. 비전 인코더 출력 직접 조사
      vision_tower(pixel_values).last_hidden_state -> (4096 패치, 1152차원) = 64x64 격자
      메커니즘: 16장의 마커 영상 특징에서 전체 평균을 뺀 뒤, 패치별 L2 편차가
                최대인 패치의 격자 좌표가 실제 마커 위치와 일치하는지 확인.
                (학습 없이, 가정 없이 위치 보존 여부만 보는 방식)
  P2. projector 통과 후 — 언어 모델이 실제로 받는 표현
      multi_modal_projector(vision_output) -> (256 토큰, 2560차원) = 16x16 격자
      P1과 동일한 최대편차 방식. 이것이 결정적 — LM 입력단에 위치가 남아 있는가.
  P3. 실제 병변에서의 쌍대(paired) 검증
      같은 흉부 X-ray에 가우시안 블러를 적용한 부드러운 병변 블롭을 삽입.
      삽입 전/후의 256 토큰 격자 차이를 계산 -> 병변 신호만 분리됨.
      대조(contrast)를 255/160/90/50으로 낮춰가며 검출 한계 확인.
      논리: 해부학 차이가 아니라 '병변 유무'만 달라지므로 교란 요인이 없음.

[해결책 검증 R1~R5 + 추가]
  R1a 사고연쇄: "먼저 위치를 한 문장으로 서술한 뒤, 줄을 바꿔 ANSWER: <번호>"
  R1b 2단계  : 모델 자신의 이전 자유서술 답변을 assistant 턴으로 대화 이력에 넣고
               "방금 서술한 위치를 근거로 몇 번 칸인가?"를 재질문
  R2 크롭    : 영상을 좌/우/상/하 절반으로 잘라 각각 "병변이 있나?" 질문.
               어느 절반에서 yes가 나오는지로 위치를 역산 (grounding 불필요)
  R3 3분할   : 절반(1비트)이 아닌 3분할로 물어 공간 해상도의 한계를 측정
  R4 가드    : "이 영상이 흉부 X-ray가 아니거나 해부구조가 없으면 그렇다고 명시하라"
               단서를 붙여 무내용 영상에 다시 질문
  R5 모달리티 힌트: "This is an axial CT slice of the body."를 앞에 붙여 CT 판독 개선 확인
  R6 로그확률 슬라이딩 윈도우:
               생성된 단어 대신 첫 토큰의 logit에서 logP(yes)-logP(no)를 계산.
               3x3 크롭 9개의 점수 중 argmax를 위치로 예측.
               메커니즘: 생성 단어는 이산적이라 변별력이 죽지만 확률은 연속값이라
                         미세한 차이도 포착 가능.
               공정성 통제: 정답이 중앙에 몰린 실제 데이터 대신, 실제 X-ray에
                           병변을 9칸 중심에 균등 삽입한 27장으로 재검증.
  R7 선형 readout:
               4개 기저 영상 x 25위치(5x5) = 100장을 병변 삽입으로 생성.
               256 토큰의 토큰별 L2 노름(256차원)을 특징으로 ridge 회귀.
               leave-one-BASE-IMAGE-out — 학습에 없던 해부구조로 일반화되는지 검증.
               논리: 동결된 특징에 선형 readout만 얹어도 되는지가
                     "가벼운 파인튜닝으로 해결 가능한가"의 대리 지표.


================================================================================
9. 원인 규명 결과
================================================================================

[9-1] bbox는 지각이 아니라 템플릿 (추론 없이 확인)
  30개 bbox 답변 중
    x_min == y_min 이 정확히 일치       : 24/30 (80%)
    박스 중심이 (0.5, 0.5)에 위치        : 22/30 (73%)
    실제 값들: [0,0,1,1], [0.15,0.15,0.85,0.85], [0.25,0.25,0.75,0.75] 등
  -> 축 대칭 라운드 숫자. 영상을 본 추정이라면 x_min과 y_min이 80%나 정확히
     같을 수 없음. 생성된 상투적 템플릿임이 확정.

[9-2] E1 합성 마커 — 거대한 흰 원도 못 지목
  격자 정확도       : 2/16 (우연 1/9=0.11과 동일 수준). 12/16이 "5"
  bbox 평균 IoU     : 0.026, IoU>=0.5는 0/16. 16건 중 14건이 [0,0,1,1]
  좌우 절반         : 7/16 (우연 이하)
  상하 절반         : 12/16 (우연 초과)
  -> 의료 판독 난이도의 문제가 아님. 위치를 말하는 능력 자체의 문제.

[9-3] E2 무내용 영상 — 영상 의존성 0, 그러나 지각은 살아 있음
  균일 회색 + 격자 질문      -> "cell **5**" (확신)
  균일 회색 + bbox 질문      -> "[0.0, 0.0, 100.0, 100.0]"
  균일 회색 + 소견 기술 요구 -> 정상 흉부 X-ray 판독문을 완성해서 생성
  균일 회색 + 모달리티 질문  -> "grayscale image" (정확)
  순수 노이즈 + 소견 기술    -> "미만성 간유리음영(ground-glass opacity),
                                crazy paving 패턴" 이라며 상세히 날조
  순수 노이즈 + 모달리티 질문 -> "Noise" (정확)
  -> 결정적 해리(dissociation): 중립적으로 물으면 내용이 없다는 것을 정확히 인지.
     전제를 깔고 물으면 전제에 순응해 지어냄. 지각 실패가 아니라 전제 순응.

[9-4] E3 — '긍정 편향' 가설은 반증됨
  말이 안 되는 소견(뇌종양/충치/대퇴골 골절) 30건 -> yes 0건 (0/30)
  부정형 표현 30건 -> 26/30 정확
  이진 질문 전체의 yes 비율 -> chexpert 0.231, nih 0.182
  -> 무분별하게 yes라고 하지 않음. 표현 트릭에도 흔들리지 않음.
     내가 처음 세운 '과다 긍정' 가설은 틀렸음.

[9-5] 낮은 정밀도의 진짜 원인 = 기저율 (수식으로 확증)
  chexpert: 유병률 16/130=0.123, 민감도 0.500, 특이도 0.807
            -> 기저율 공식이 예측하는 정밀도 0.267 / 실측 0.267 (완전 일치)
  nih     : 유병률 13/132=0.098, 민감도 0.308, 특이도 0.832
            -> 예측 0.167 / 실측 0.167 (완전 일치)
  정밀도 0.8을 얻으려면 필요한 특이도: 0.982(chexpert) / 0.992(nih)
  -> 모델 성향 문제가 아니라 불균형 다중라벨 평가의 구조적 귀결.
     accuracy만 보고하면 성능을 심각하게 오해하게 됨.

[9-6] E5/E6 — 출력 형식이 전부를 좌우함
  빈 캔버스(해부학 없음) 마커, 같은 능력을 4가지 형식으로 질문:
    격자 번호                          : 0/4  (전부 "5")
    "LEFT or RIGHT" 이분 선택 (n=16)   : 8/16, 16회 전부 "left"
    "RIGHT or LEFT" 순서 뒤집기 (n=16) : 8/16, 16회 전부 "right"
    "TOP or BOTTOM" (n=16)             : 15/16, p=0.0003 (위치를 추적함)
    "BOTTOM or TOP" 순서 뒤집기 (n=16) : 8/16, 16회 전부 "bottom"
    숫자 추정 (n=32, 양축)             : 32회 전부 정확히 "0.5"
    순서 없는 빈칸 채우기 — 좌우       : 14/14, p=0.0001
    순서 없는 빈칸 채우기 — 상하       : 9/10,  p=0.011
  -> 이분 선택은 첫 번째 선택지를 고르는 순서 편향에 지배됨.
     숫자를 요구하면 정보량 0의 상수.
     그러나 선택지를 제시하지 않고 문장을 완성시키면 양축 모두 정확.
     즉 공간 정보는 있는데, 제약된 출력 형식이 그것을 덮어버림.

[9-7] E7 실제 병변 — 관례를 바꾸면 75%
  영상 좌표 기준 채점   : 6/24 = 0.25  (우연보다 유의하게 낮음 = 체계적 반전)
  방사선학적 관례 채점  : 18/24 = 0.75, p=0.011 (brats 6/7, deeplesion 6/9, vindr 6/8)
  상하 (토큰 한도 수정 후 재측정): 13/17 = 0.76, p=0.025
  -> 프롬프트에 "영상 프레임 기준"이라고 명시했는데도 모델은 환자 기준으로 답함.
     지시를 무시하고 임상 관례를 고수. 관례에 맞춰 채점하면 정확도가 뚜렷.

[9-8] 모델 내부 프로브 — 정보는 어디까지 살아 있는가 (핵심)
  P1 비전 인코더 출력 (4096 패치 = 64x64, 1152차원)
     마커 16/16 위치 추적 성공
  P2 projector 통과 후, 언어 모델이 실제로 받는 표현 (256 토큰 = 16x16, 2560차원)
     마커 16/16 성공, 평균 위치 오차 0.069 이미지폭
  P3 실제 X-ray에 병변 삽입한 쌍대 검증 (6위치)
     대조 255 -> 6/6, 평균 오차 0.042
     대조 160 -> 6/6, 평균 오차 0.042
     대조  90 -> 6/6, 평균 오차 0.042
     대조  50 -> 6/6, 평균 오차 0.051  (저대조의 미묘한 병변도 검출)
  기준: 3x3 격자 한 칸의 폭은 0.333
  -> 언어 모델이 받는 신호는 격자 과제에 필요한 것보다 5~7배 세밀함.
     "못 본다"가 아니라 "본 것을 말로 옮기지 못한다"가 정확한 진단.

[9-9] 그룹 1 실패의 성격 (사례 검토)
  vqa_rad 10건 중 6건이 진짜 오답. 채점 문제가 아님. 특징적 패턴:
    "are the kidneys present in this image?" (정답 no) -> "Yes"
    "is the liver visible in the image?"      (정답 no) -> "Yes"
    "where are the kidney?" (정답 'not seen here')
        -> "The kidneys are located on either side of the spine, below the ribs."
           = 영상을 보는 대신 교과서 해부학을 읊음
  -> 9-3의 전제 순응과 같은 기전. 질문이 존재를 전제하면 존재한다고 답하고,
     영상 근거가 없으면 일반 지식으로 메움.
  kvasir 10건: 2건은 순수 채점 artifact (정답 "none" vs 모델 "No instruments are
  visible in the image." — 의미상 정답인데 F1 0). 나머지는 진짜 오답.
  데이터셋 고유 표기("none", "not relevant")가 F1 채점에 구조적으로 불리함.

10. 해결책 검증 실험과 결과
================================================================================

[R1] 프롬프트로 격자 번호를 복구할 수 있는가 — 실패
  사고연쇄 후 ANSWER 요구 : 5/30 = 0.17  (기존 11/30=0.37보다 오히려 악화.
                            예측은 다양해졌으나 정확도는 떨어짐)
  2단계(자기 서술 재활용) : 12/30 = 0.40 ("항상 5" 기준선과 동일.
                            30건 중 21건이 여전히 "5")
  -> 프롬프트 엔지니어링으로는 좌표/인덱스 출력을 복구할 수 없음.

[R2] 크롭 기반 위치 추정 (grounding 불필요) — 실제 데이터에선 그럴듯했으나 통제 실험에서 실패
  실제 병변 30장, 좌/우/상/하 절반 크롭에 "병변이 있나?" 질문:
    좌우: 변별 가능(한쪽만 yes)한 경우가 8/30뿐, 그중 정답 7/8
    상하: 변별 가능 12/30, 그중 정답 10/12
    크롭 전체의 yes 비율 84/120 = 70% -> 대부분 양쪽 다 yes라 변별 불가
  개선 시도 = R6 로그확률 방식 (아래)

[R3] 공간 해상도의 한계 — 1비트/축이 천장
  3분할(좌/중/우) : 7/30 = 0.23, 우연(0.33) 수준, 유의하지 않음.
                    답변 분포 left 22 / right 7 / center 1 로 편중
  3분할(상/중/하) : 9/30 = 0.30, 유의하지 않음. lower 18 / middle 7 / upper 5
  -> 절반 단위(약 75%)는 되지만 3분할은 우연 수준.
     자연어 유도로 얻을 수 있는 공간 정보는 축당 약 1비트가 한계.

[R4] 환각 방지 가드 — 성공 (비용 0)
  순수 노이즈 + 기본 프롬프트  -> "ground-glass opacity, crazy paving" 날조
  순수 노이즈 + 가드 단서      -> "random noise pattern이며 폐/심장/뼈 같은
                                  해부구조가 없다. 따라서 ..." (정확)
  균일 회색 + 가드 단서        -> "해부구조가 식별되지 않는 회색조 영상" (정확)
  중립 질문("이 영상이 무엇인가?") -> "의료 영상이 아니다" (정확)
  -> 프롬프트에 탈출구 한 줄을 넣는 것만으로 환각이 사라짐. 효과 확인됨.

[R5] 모달리티 힌트 — 부분 개선
  "This is an axial CT slice of the body."를 앞에 붙였을 때
  여전히 X-ray라고 답한 비율: 4/10 -> 2/10
  -> 절반 개선. 근본 해결은 아님.
  (주의: 이 실험에서 max_new_tokens=64가 일부 장황한 답변을 잘랐음.
   X-ray 오인 집계 자체는 유효하나 정밀한 비교는 아님)

[R6] 로그확률 슬라이딩 윈도우 — 실제 데이터에선 기준선 미달, 통제 실험에선 실패
  방식: 3x3 크롭 9개 각각에 대해 첫 토큰 logit에서 logP(yes)-logP(no)를 계산,
        argmax를 위치로 예측
  실제 병변 30장 : 13/30 = 0.43  ('항상 5' 기준선 14/30 = 0.47 에 미달)
                   단, 예측이 영상에 따라 변하긴 함(생성 텍스트 방식과 달리 상수 아님)
  통제 실험 (실제 X-ray 3장에 병변을 9칸 중심에 균등 삽입한 27장):
                   4/27 = 0.15, 유의하지 않음
                   예측 분포가 2번/3번/4번 칸에만 몰림 (5~9번은 한 번도 예측 안 함)
  -> 크롭의 yes 점수가 '병변 유무'가 아니라 '크롭에 담긴 해부구조'에 반응.
     추론 단계 트릭으로는 해결 불가.

[R7] 동결 특징 + 선형 readout — 신호는 있으나 아직 쓸 수준 아님
  데이터: 기저 영상 4장 x 25위치 = 100장 (병변 삽입, 정확한 라벨)
  방식  : 256 토큰의 토큰별 L2 노름(256차원) -> ridge 회귀,
          leave-one-BASE-IMAGE-out (학습에 없던 해부구조로 테스트)
  결과 (lam=1000):
          x(수평) r = +0.653,  MAE = 0.178
          y(수직) r = +0.495,  MAE = 0.181
          평균 예측 MAE = 0.180  (3x3 한 칸 = 0.333)
  -> 처음 보는 해부구조에서도 상관은 뚜렷하게 양(+). 위치 신호가 선형으로
     디코딩 가능함을 시사.
     그러나 MAE가 평균 예측과 동일 = 아직 실용 정확도가 아님.
     단, 이 특징은 토큰당 2560차원을 L2 노름 하나로 뭉갠 조악한 것이므로
     디코딩 가능성의 하한으로 봐야 함.

================================================================================
과도한 일반화를 막기 위해 주장별 근거 강도를 명시함.

[강하게 증명됨 — 통제 실험 또는 쌍대 비교]
  - 위치 정보가 LM 입력단(256 토큰)에 정밀하게 도달한다
    (마커 16/16 오차 0.069, 삽입 병변 6/6 오차 0.042~0.051, 저대조에서도 유지)
  - bbox 출력은 지각이 아니라 템플릿이다 (80% 축대칭, 무내용 영상에서도 동일 출력)
  - 이분 선택은 선택지 순서 편향에 지배된다 (순서를 뒤집으면 답이 따라 뒤집힘)
  - 숫자 좌표 요구는 정보량이 0이다 (32/32 전부 "0.5")
  - 긍정 편향은 없다 (말이 안 되는 소견 0/30, 부정형 26/30)
  - 낮은 정밀도는 기저율의 귀결이다 (공식 예측 = 실측, 소수점 3자리 일치)
  - 전제를 주면 환각하고 중립적으로 물으면 정확하다 (동일 영상 대조)
  - 가드 단서가 환각을 없앤다 (무내용 영상 2종 모두에서 확인)
  - 프롬프트/추론 트릭으로 격자 정확도를 개선할 수 없다
    (사고연쇄 악화, 2단계 = 기준선, 로그확률 슬라이딩 윈도우 통제실험 4/27)

[통계적으로 유의하나 표본이 작음]
  - 실제 병변 좌우 75% (18/24, p=0.011)
  - 실제 병변 상하 76% (13/17, p=0.025)
  - 빈 캔버스 상하 15/16 (p=0.0003), 빈칸 채우기 좌우 14/14 (p=0.0001)
  - 3분할은 우연 수준 (7/30, 9/30 — 유의하지 않음)

[추론이며 아직 검증되지 않음 — 반드시 실측 필요]
  - "가벼운 LoRA 파인튜닝이면 localization이 해결된다"
    근거: 특징에 위치 정보가 있고 매핑만 없다는 구조적 논리.
    반례성 데이터: 조악한 선형 프로브는 상관 r=+0.65/+0.50을 보였으나
                   MAE가 평균 예측과 같아 아직 실용 수준이 아님.
    -> VinDr 박스로 소규모 LoRA를 실제로 돌려 IoU를 측정해야 확정 가능.

[일반화하면 안 되는 것 — 표본 한계]
  - 데이터셋당 10장(SLAKE만 QA 82개). 벤치마크 수치가 아니라 정성적 스모크 테스트.
  - NIH 10장 중 7장이 Hernia, Kvasir 10장 전부 궤양성 대장염으로 편중.
  - CheXpert/NIH는 비공식 커뮤니티 미러. 라벨 신뢰도가 원본 배포판과 다를 수 있음.
  - 논문용 수치가 필요하면 각 데이터셋 test split 전체로 확장해야 함.
