새로운 학습보다 예상 GPU 비용은 작지만, 의미 확인이 지배 비용일 수 있다. 현재 그 시간은 미측정이다. 한 번의 사례 적합성 확인으로 질문이 성립하지 않으면 보류한다.

# Contribution Path / Baselines / Reuse

기여는 미확정이다. [CURE](https://arxiv.org/abs/2601.15408), [Anatomically-Grounded Fact Checking](https://arxiv.org/abs/2412.02177), [RadSCR](https://proceedings.iclr.cc/paper_files/paper/2026/hash/7e966a12c2d6307adb8809aaa9acf057-Abstract-Conference.html)은 가까운 선행이다. 영역 정보 기반 교정 자체를 novelty로 삼지 않는다. 이번에는 어떤 정보가 실제 도움이 되는지와 강한 단순 대안 이후의 잔여 문제를 확인한다.

필수 대조는 다음 다섯 개다.

1. **K:** C-G 초안 유지.
2. **A:** C-G에 아래 고정 영역 설명을 추가. 공백 정규화 후 정확히 동일한 설명만 중복 제거하며 의미 기반 선택·충돌 제거는 하지 않는다.
3. **N:** 영상+초안, 추가 근거 없음.
4. **T:** 영상+초안+영역 설명 본문.
5. **L:** T와 같은 설명 본문·순서·묶음에 실제 질의 영역 이름을 추가.

N/T/L은 같은 MedGemma 1.5와 지시를 사용한다. A는 T와 동일한 문장 집합을 사용한다. K/A는 GPU 요청이 없다. 입력 token 수와 생성 비용 차이를 보고한다.

현재 브랜치 HEAD `e26d1ad7f499186434639bb0d1e908d27ce5c4f5`를 유지한다. 다음 파일은 이미 존재하므로 선별 반입하지 않는다.

- `report86_common.py`: hash·배타 저장 도구 재사용. 출력·cache는 iter_098로 격리한다.
- `report86_view.py`, `report87_eval.py`, `report88_adjudicate.py`: 기존 출력·reference·span 연결을 읽는 경로만 재사용한다. 기존 hardcoded 의미 판정을 새 출력에 적용하지 않는다.
- `report97_gen.py`, `report90_gen.py`, `report90_gen_safe.py`, `report90_recovery_gen.py`와 연결된 `report90_recovery_train.py`, `report90_train.py`, `report90_numeric.py`, `report90_stable.py`, `report90_stable_v2.py`, `report89_model.py`, `rsna_diag/generate.py`, `rsna_diag/lora.py`: 현재 추론 경로를 최소 확장한다. 실제 import 의존성을 manifest에 기록하고 source digest에 빠진 경로를 포함한다. checkpoint 없이 base를 실행할 때 새 LoRA가 출력에 영향을 주지 않는지 확인한다.

iter_097의 생성기 needs_fix는 재사용 전에 해결한다. 허용 GPU 집합 검사, 비정상 종료 후 attempt 충돌, source/config 변경·동시 중복·완료 변조 거부를 이번 실행 경로에서 검증한다. 과거 평가기와 학습 launcher의 무관한 결함은 수정하지 않는다.

# Proposed Experiment

## 1. 자료 적합성과 평가 규약 잠금

후보는 기존 E96의 비정상 48명으로 고정한다. 정상 층이나 E192로 후보를 늘리지 않는다. 기존 linked 판정은 탐색 색인으로만 사용하며 원문을 확인한다.

각 환자에 대해 C-G가 명확히 표현한 reference-supported 사실 집합 P와, 영역 설명에는 있으나 C-G에는 없는 명확한 양성 사실 집합 Q를 기록한다. 부위·양측성·부정·확실성·속성을 원자 단위로 나눈다. P와 Q가 모두 비어 있지 않은 환자를 회복 집단 N으로 한다. 포괄 정상문만으로 구체적 정상 사실을 보존했다고 인정하지 않는다. 시간 표현은 현재 소견과 별도 항목으로 두며 단일 영상으로 새 발생·호전을 검증했다고 하지 않는다.

이 선택은 회복 기회를 의도적으로 모은 개발 진단이다. 자연 모집단의 빈도 추정으로 해석하지 않는다. 명확한 적격자가 한 명이라도 있으면 사례 탐색은 허용하되, 적은 수로 아래 투자 기준을 충족했다고 하지 않는다. 적격자가 없으면 생성 없이 보류한다.

나머지 비정상 환자 중 P가 있고 Q가 없는 환자를 고정 hash 순으로 최대 N명 추가한다. 이들은 근거 제공이 불필요한 수정·손상을 만드는지 보는 보존 대조다. 총 M≤48이다. 추가 대조가 부족하면 실제 수를 그대로 사용한다.

먼저 P008/P033/P053 등 대표 후보의 원 reference와 전체 출력 문맥을 확인하여 규약이 질문을 판별하는지 점검한다. 이후 동일 규약으로 48명 내 적격성을 한 번 확정한다. 모호성 때문에 규약을 반복 변경하지 않는다. 환자 선택·P/Q·모호 항목·제외 사유를 신규 생성 전에 잠근다.

## 2. 입력 구성

모든 환자에게 저장된 29개 영역 출력 전체를 같은 규칙으로 사용한다. GT에 맞는 문장만 선택하지 않는다. 각 출력에서 형식적으로 분리 가능한 `Description` 본문을 추출하고 좌표·`Location of ...` 헤더만 제거한다. 본문의 좌우·해부학 표현·부정·불확실성·시간 문구는 수정하지 않는다. 동일 본문은 정확 문자열 기준으로 묶고 T에는 중립 ID, L에는 같은 ID와 원 질의 영역 이름 목록을 붙인다. 순서는 원 source 순으로 고정한다.

이는 예측 영역 출처이며 정답 위치라는 안내를 붙이지 않는다. 설명이 지정 영역 밖을 언급해도 임의로 고치지 않는다. 추출 실패는 별도 기록하고 기술적으로 해결되지 않으면 해당 입력 경로를 중단한다. 내용이 마음에 들지 않는다는 이유로 문장을 제거하지 않는다.

초안은 C-G에서 좌표 표기만 제거한 동일 텍스트를 전 조건에 쓴다. N은 근거 목록이 빈 동일 template를 사용한다. 지시는 영상으로 초안을 검토하고, 추가 설명도 오류가 있을 수 있음을 알리며, 지지되는 내용을 보존하고 근거가 있는 수정만 하도록 고정한다. 모델에는 reference·P/Q·기존 평가 라벨·정답 bbox를 제공하지 않는다.

## 3. 동작 확인

기존 D8에서 본평가와 환자·study가 겹치지 않는 4명을 고정하여 세 조건 12요청을 구성한다. 입력이 긴 사례도 포함한다. 목적은 tensor·길이·EOS·메모리·재개 확인이다. 내용 정답률로 prompt를 고르거나 100% 정답을 gate로 요구하지 않는다.

greedy, seed17, 기존 cap 1024→2048→4096의 비EOS 확장 규칙을 전 조건에 동일 적용한다. 최종 비EOS·형식 실패를 분모에서 빼지 않는다. 입력을 조용히 잘라내지 않는다. 문맥 길이 부적합이면 근거를 사후 선택하지 말고 기술 blocker로 보고한다.

## 4. 가능성 탐색

잠근 M명에 N/T/L을 각각 한 번 생성한다. 신규 기본 요청은 3M≤144건이다. K/A도 동일 사실 규약으로 평가한다. 저장 출력은 환자·조건별 원자적 완료와 hash로 봉인한다.

## 5. 규모 확대와 독립 확인

이번 반복에서는 추가 환자·seed·학습·모델을 자동 실행하지 않는다. 양성 기준을 충족하면 full review에서 지지된 요소와 의미 불확실성을 확인한 뒤 별도 독립 확인 또는 method pilot을 계획한다. 현재 E 자료를 독립 test로 부르지 않는다.

5. 기술 요청으로 정상 입력·중단 재개·중복 거부·변조 거부와 병렬 처리량을 확인한다. 실패 attempt도 삭제하지 않는다.

7. 원시 사실 표에서 별도 산술 경로로 paired 지표와 투자 분기를 재계산한다. 동일 의미 라벨의 산술 재계산은 독립 의미 검증이 아님을 적는다.

## GPU·시간·재개

실행 직전 `nvidia-smi`로 허용된 0,1의 여유를 확인한다. 기존 CURE 짧은 요청에서는 4 worker 이득이 있었지만 이번 긴 입력으로 그대로 승인하지 않는다. 기술 12요청을 2 worker와 안전할 경우 4 worker에서 비교한다. 동시 peak 합계·외부 점유에 worker당 2GiB 여유를 더해 수용 가능한 경우만 실행한다. 4 worker가 불가능하면 이유를 기록하고 2 worker 또는 batch 확대 중 실행 가능한 한 후보를 검토한다.

두 GPU에 독립 요청 shard를 분산한다. 유효 요청/분, 입력·출력 token, 긴 요청 지연, reserved/allocated 및 장치 peak, OOM·CPU/I/O 경합을 기록한다. 출력 token 정합성을 확인한 구성을 택한다. 실행 구성을 성능 결과로 선택하지 않는다.

현재 wall-clock은 미측정이다. 기술 단계의 합산 처리량 q로 `남은 요청/q + loading`을 계산하고 긴 출력 확장 비용을 별도 더한다. 의미 검토 시간도 별도 기록한다. 과거 CURE의 9.44/14.66 req/min은 참고이며 이번 예상치로 대입하지 않는다. 임의 시간 상한은 두지 않는다.

worker별 고유 파일·고정 요청 ID·원자적 할당·completion hash로 재개한다. 장시간 대기는 supervisor와 `../experiment_wait.py --pid <PID> --timeout 600` 또는 동등한 완료 대기를 사용한다. 기본 환경·hf_cache를 변경하지 않는다. 필요한 격리 환경 변경은 사전 알림 후 승인 범위에서 수행한다.

# Evaluation (성공/실패 기준 포함)

평가 단위는 환자와 고정 사실 ID다. 원자 사실 수준에서 다음을 분리한다.

- Q의 명확한 회복 수·비율 및 회복 환자 수.
- P의 동일 사실 보존, 삭제, 부정 전환, 위치·속성 손상.
- reference가 명시적으로 반박하는 새 주장과 출력 내부의 명확한 충돌.
- reference에 없는 검증 불가 주장. 이를 정상 또는 확정 오류로 강제하지 않는다.
- 비EOS·형식 실패·출력 길이와 추론 비용.

**안전한 회복 환자**는 Q에서 적어도 한 사실을 회복하고 P를 모두 보존하며, K 대비 새 명시 반박·내부 충돌이 없는 환자다. 이 명칭은 reference 범위의 운영 지표이며 임상 안전성을 뜻하지 않는다. 검증 불가 주장이 늘어난 환자는 별도 표시하고, 그 증가 환자를 성공에서 제외하는 보수적 분석도 수행한다.

paired 환자 bootstrap 10,000회·seed98017과 leave-one-patient-out을 기술적으로 보고한다. 작은 표본에 CI 유의성을 보편적인 실행 gate로 부과하지 않는다.

**양성 탐색:** T 또는 L이 K 대비 안전한 회복을 최소 3명의 서로 다른 환자에서 보이고, N과 A 각각 대비 안전한 회복 환자 순증가가 최소 2명이며, P 손상·명시 오류 환자가 각 대조보다 증가하지 않아야 한다. 모호 사실 제외와 검증 불가 증가 제외에서도 방향이 유지되어야 한다. 이는 몇 건의 단일 사례 이득만으로 수 시간 학습을 발주하지 않기 위한 탐색 투자 기준이지 임상 효과 문턱이 아니다.

**출처의 추가 가치:** 위 조건에 더해 L−T의 안전한 회복 순증가가 최소 2명이고 보존·오류 악화가 없어야 한다. 충족하지 않으면 문장 내용 효과와 출처 효과를 구별하여 후자 주장을 보류한다.

**음성:** 명확한 기회가 있으나 T/L이 N 또는 A를 개선하지 못하거나 회복 이득이 정답 손상으로 상쇄되면 현재 인터페이스 투자를 보류한다. A가 충분하면 단순 추가가 이 선택 집단에서 설명한 범위를 받아들인다. 모델 기본 수정 수행이 부족하면 그 조건의 적합성 부족으로 한정한다.

**불확정:** 사례 수 부족, 검증 불가 주장 증가, 의미 대응에 따른 결정 반전이면 사례 결과를 보존하고 현재 투자를 보류한다. 동일 E 자료의 prompt·규칙·표본을 더 조정하지 않는다. 새로운 독립 정답 근거가 어느 사례와 투자 결정을 바꿀지 특정할 때만 후속 보완을 검토한다.

기술 실패·자료 부적합·실제 음성 관찰은 별도 보고한다. 자료 점검만 마쳤다면 새 가설 검증으로 기록하지 않는다.

# Risks / Checks

- 포괄 정상문, lobe–zone 동치, 부분적 양측 회복, 시간·원인 hedge를 자동 대응하지 않는다. unknown을 유지한다.

## 가까운 선행

- [CURE](https://arxiv.org/abs/2601.15408)는 phrase grounding·grounded report·anatomy-grounded report를 함께 학습한다. 이번 교정은 저장 출력의 새로운 활용 조건이며 공식 성능 재현 시험이 아니다.
- [Anatomically-Grounded Fact Checking](https://arxiv.org/abs/2412.02177)은 소견과 위치 오류를 검출하고 보고서 교정에 사용하는 선행이다. 영역 근거를 이용한 교정 자체를 새 기여로 주장할 수 없다.
- [RadSCR](https://proceedings.iclr.cc/paper_files/paper/2026/hash/7e966a12c2d6307adb8809aaa9acf057-Abstract-Conference.html)은 영역별 소견 제안을 검토한 뒤 보고서로 종합한다. 이번 진단의 양성이 곧 이 계열 대비 우위를 뜻하지 않는다. 본문·공개 구현의 세부 비교는 방법 투자 결정 시 확인할 범위다.
