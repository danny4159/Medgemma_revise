# 사고 라운드 1

## 새로 확인한 것

이번 라운드는 문서·소스·논문 조회와 저장 출력의 읽기 전용 재집계만 수행했다. 파일 수정·생성, 모델 로딩, GPU 추론·학습은 수행하지 않았다.

### 1. 기존 성과와 종료된 질문

`agent/GOAL.md`, `agent/REPORTING_STYLE.md`, `agent/LIMITATIONS.md`, `agent/CODE_ASSETS.md`, iter_027 원본 리뷰·보고서, iter_012–018 계획·리뷰의 관련 부분, iter_026 계획·조사 기록과 현재 소스를 대조했다.

- iter_012의 RSNA 직접 LoRA SFT 개선은 유지한다. 확인 양성 400명의 F1@0.3은 base official 0.165, SFT 세 seed 0.631–0.653이다. 특정 추가 loss의 실패는 이 성과의 기각이 아니다.
- iter_015–018은 전역 QA 형식 효과와 검출·개수·좌표 전달의 차이를 조사했다. 이들을 새 이름으로 반복하지 않는다.
- iter_027은 현재 직접 사분면 선택의 사전 음성 기준을 충족했다. primary 160명의 B0−M0 S는 +0.194292지만 B0−Copy_B0는 +0.018060, 95% CI [−0.004103, 0.042368]이다. 다중 사분면 66명의 전체 선택은 직접 B0 0명, 규칙 26명이다.
- 이 결과는 현재 인터페이스의 신뢰할 만한 전체 선택이 확보되지 않았다는 근거다. 부분 반응이 없거나 모든 공간 전이가 실패했다는 증거는 아니다. E200은 개발 자료다.

사용자 보완 중 기존 checkpoint 진단 우선순위와 원본 보존은 유지한다. 기존 E 확대는 종료하고 새 loss·학습·seed 확대는 보류한다. MRI F139·reserve·iter_022 longitudinal 계획을 자동으로 열지 않는다.

### 2. 이번 재분석: oracle은 출력 schema 실패만으로 설명되지 않는다

`research/rsna_diag/roi26_spec.py`의 O_TMPL과 `roi26_requests.py::build_o`에서 입력은 숫자 배열 목록인데 출력 지시는 원래 `box_2d`·`label`을 변경 없이 반환하라는 불일치를 확인했다. 이는 보정할 입력 계약 문제다. 그러나 실제 응답이 어떻게 실패했는지는 별도로 봐야 한다.

`research/results/iter_026/requests/D_O__{M0,B0}.jsonl`과 대응 `gen/D_O__{M0,B0}/gen_worker*.jsonl`을 연결했다. D24 환자×4영역으로 모델별 96건이다. 제공된 정수 bbox의 중심에서 정답 부분집합을 직접 계산하고, 좌표 목록을 정렬해 순서와 무관하게 정확히 비교했다. 아래는 사후 개발 분석이며 기존 주지표나 판정을 대체하지 않는다.

| D24 oracle 분석 | M0 | B0 |
|---|---:|---:|
| 기존 bbox parser에서 유효한 출력 | 96/96 | 96/96 |
| 제공 목록에 없는 좌표를 반환한 응답 | 0/96 | 0/96 |
| 제공 전체 목록을 그대로 반환 | 90/96 | 25/96 |
| 정답 부분집합과 좌표가 정확히 일치 | 14/96 | 44/96 |
| 빈 정답 질의에서 정확한 빈 목록 | 4/57 | 22/57 |
| 비어 있지 않은 진부분집합 질의에서 정확한 선택 | 0/29 | 14/29 |
| 전체 목록이 정답인 질의에서 정확한 선택 | 10/10 | 8/10 |
| 네 질의 모두 동일 좌표 목록인 환자 | 20/24 | 9/24 |

29개 진부분집합 질의에서 M0는 모두 전체 목록을 반환했다. B0는 14건을 정확히 골랐고, 9건은 빈 목록이었다. 두 모델 모두 제공 좌표를 읽어 유효한 출력 schema로 바꾸는 동작은 했다. 따라서 현재 실패를 parser 오류나 좌표 전사 실패로만 설명할 수 없다. 반대로 이 관찰로 입력 계약의 불일치가 무해하다고 입증한 것도 아니다.

독립 파싱은 완결 thinking marker 뒤 답변과 code fence·종료 token을 분리한 후 JSON 전체를 읽었다. 처음 단순 whole-string 처리에서 M0 11건의 뒤쪽 code fence를 처리하지 못했으나, 원문 확인 후 이를 분리했고 기존 parser와 좌표 불일치 0/192를 확인했다. 위 표는 192건 전체에 대한 최종 집계다.

사분면 이름의 모든 전역 순열 24개를 적용한 사후 대조에서도 최대 정확 일치 수는 M0 14/96, B0 44/96으로 원래 mapping보다 높아지지 않았다. 단일한 좌우·상하·축 교환으로 전체 오류가 해결되지는 않는다. 개별 응답의 축 혼동이나 복합 원인을 배제하는 검사는 아니다.

### 3. 이 관찰이 바꾸는 해석

전체 네 질의를 모두 맞혀야 하는 Q4_select=0과 부분 선택 능력은 양립한다. B0의 14/29는 그 구분을 실제 출력에서 보여준다. 그러나 GT 목록을 제공했으므로 시각적 위치 정보가 전이됐다는 증거가 아니다. 이미지가 필요 없는 목록 처리, bbox 형식 적응, 영상의 간섭, 지시 해석이 경쟁 설명으로 남는다.

따라서 schema를 고친 oracle 한 조건이 성공했다는 이유만으로 직접 영상 질의의 실패 원인을 확정하거나 새 학습에 진입해서는 안 된다. 최소 검사를 한다면 보정한 입력 계약의 효과와 영상 유무 효과를 구분할 수 있어야 한다. 계산된 사분면 정답을 제공하는 대조는 기존 AR처럼 답 읽기 sanity에 한정해야 한다.

## 선행 방법과 추가 조사 범위

이번 문헌 재확인은 이미 조사한 내용을 반복 수집하기 위한 것이 아니다. 입력 계약 보정 이후 어떤 후속 방법이 기존 연구와 구별될지, 전환 후보가 이미 단순 baseline 수준인지 확인했다.

- [Why Does Grounding Hurt Medical VQA?](https://arxiv.org/html/2604.27720v2)의 §4와 학습 상세는 shuffled-box 형식 rehearsal과 실제 grounding supervision을 분리한다. 이번에는 출력이 이미 모두 유효하고 좌표도 제공 목록에서 나왔으므로 형식 복구만을 주된 기여 경로로 삼기 어렵다. 해당 연구와 현재 RSNA bbox-only 적응은 학습 방향·과제가 달라 결과를 그대로 이식할 수 없다.
- [CURE](https://arxiv.org/html/2601.15408v1)의 §7.4와 §9.2를 확인했다. 다중 grounding 과제 학습뿐 아니라 VinDr-CXR 외부 평가와 bbox-aware augmentation도 다룬다. 따라서 다른 데이터에서 점수를 재거나 통상적인 공간 증강을 적용하는 것만으로 새 기여가 되지는 않는다. 논문의 학습 미사용 주장을 foundation model의 사전학습 미노출로 확대하지 않는다.

두 논문은 방향 판단의 근거다. 이번 라운드는 사용자에게 새 논문을 추천하는 단계가 아니다.

## Strategy Check / 연구 방향 판단

중요한 능력은 전문 과제로 적응한 의료 VLM이 그 성과를 다른 지시에 맞춰 사용할 수 있는가이다. 현재 확보한 사실은 검출 개선, 직접 전체 선택의 실패, 규칙 baseline의 우위, oracle에서의 부분 선택 변화다. 일반적 시각 전이와 새 방법의 필요성은 미확정이다.

1. **최소 원인 진단:** 기존 환자·checkpoint를 활용해 제공 목록 처리와 영상 조건부 반응을 분리할 수 있다면 정보 이득이 있다. 이번 14/29 관찰 때문에 전체 실패만으로 종료하기보다 검토할 가치가 있다. 다만 schema 보정 이후에도 모든 결과가 막연한 추가 prompt 탐색으로 이어진다면 실행하지 않는다.
2. **다른 연구 질문:** 동일 opacity 검출에서 외부 원천으로의 전이와 미검출 신뢰도를 조사하는 후보를 비교할 수 있다. SFT의 실용적 확장성과 연결되지만 annotation 범위·기관 차이·정답 대응 및 가까운 선행 대비 실패 조건을 확인해야 한다. 현재 접근 가능성이나 신규성을 검증한 후보는 아니므로 즉시 전환하지 않는다.
3. **현재 grounding 방법 개선:** validated 위치 오류와 잔여 오류는 있지만 새 loss가 이번 선택 단절을 해결한다는 연결이 없다. 기존 직접 SFT 및 규칙보다 추가 투자 우선순위가 낮다.

잠정 1순위는 최소 원인 진단의 설계를 확정하는 것이다. 이번 think_more의 목적은 이 검사가 실제로 학습 투자 또는 종료·전환을 가르는지 정하는 데 있다. 기존 E200의 정밀도를 더 높이는 목적은 아니다.

## 실제 자산과 재사용 범위

현재 research HEAD는 `ed966685298f152e194069d4de3d856e065886bc`이며 `git status --short`와 `git diff --stat`는 비어 있었다. `roi26_*`, `roi23_*`, `parse.py`, `metrics.py`, `generate.py`와 관련 실행 파일이 현재 브랜치에 존재한다. 같은 접근법을 이어가는 잠정안에서는 별도 선별 반입이 필요하지 않다.

B0는 `research/results/iter_012/train/lr2e-4_s17/epoch_05/adapter.pt`다. 이번에 계산한 파일 SHA256은 `5f542af96df705e567bf4cfb000398b09313db2456c577e772bd76481799cf29`로 iter_026 조사 기록과 일치했다. 저장 checkpoint manifest의 tensor digest는 `e13f3c4461b826a060c90dfe4e4ee4c2ebac36a08f84be1a45a37495816cec11`이다. 이번에는 tensor 재계산이나 실제 adapter 로드를 수행하지 않았다.

승인 범위는 기존 parser·matching·bootstrap 등 제한된 모듈이다. 실행기를 재사용한다면 실제 선택한 경로의 필수 source·checkpoint·예상 요청 행렬 잠금, 평가 진입점 검증, 단계 decision, 완료 재사용, 통제된 중단·재개 검사가 필요하다. 기존 seed gate와 C_query 확대식은 미수정 결함이므로 새 설계에 그대로 연결하지 않는다. 과거 report 덮어쓰기의 byte 단위 복구 가능성은 아직 조사하지 않았으며, 원시 출력으로 재계산 가능하다는 이유로 정보 손실이 없다고 보고하지 않는다.

두 GPU 활용 방침을 유지한다. iter_027의 2-worker 24건과 4-worker 23건은 완결된 동등 작업량 처리량 비교가 아니다. 구현을 선택하면 같은 개발 요청의 2/4 worker 또는 batch 확대를 비교하고, worker당 2GiB 여유·긴 출력 peak·출력 정합성으로 구성을 결정해야 한다. 새 비용과 wall-clock은 아직 측정하지 않았다.

## 대규모 GPU 필요 후보

다기관 grounding·영역 질의·일반 QA를 결합한 vision encoder–언어 모델 공동 post-training을 보존한다. 충분한 batch·다수 seed·외부 확인을 포함한 전체 규모에는 더 큰 메모리와 처리량이 필요할 수 있다. 현재 필요성과 신규 기여는 미확정이며, 두 24GB GPU에서 가능한 경량 적응까지 배제하는 근거로 쓰지 않는다.

## 다음 조사로 결정할 것

최소 입력 계약 대조의 식별력과 종료 조건을 먼저 확정한다. 이를 통해 후속 투자가 달라지지 않는다면 추가 GPU 진단을 만들지 않고 구체적인 대체 질문의 자료·비교군을 확인한다. 기존 결과와 현재 사후 분석은 개발 근거로만 사용하며 독립 확인으로 승격하지 않는다.
