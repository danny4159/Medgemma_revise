# 사고 라운드 1

## 핵심

기존 범위 진단의 자동 연장을 보류하고, **다중 영상에서 소견과 해당 영상을 올바르게 연결하는 능력**을 잠정 1순위 조사 대상으로 정했다. 아직 구현할 과제는 확정하지 않았다. 새로 확인한 공개 자료는 실행 가능성을 높이지만, 합성 변화와 실제 임상 변화가 섞여 있어 자료 이름만 보고 temporal 연구로 선택하면 안 된다.

이번에는 문서·코드·기존 기록과 공개 선행 자료만 읽었다. 파일 생성·수정, 다운로드 저장, 모델 로딩, 실험 실행은 하지 않았다.

## 확인한 기존 근거와 유지할 판단

`agent/GOAL.md`, `agent/LIMITATIONS.md`, `agent/CODE_ASSETS.md`, `agent/REPORTING_STYLE.md`, 자원·Claude 정책, iter_003·009·012·018 원본 리뷰, iter_018의 이전 조사 기록, legacy 문서의 중대 정정을 확인했다. 전달된 INDEX·JOURNEY와 최신 연구 운영 정책을 함께 적용했다.

- 정상 사용 RSNA grounding 오류와 직접 SFT 개선은 유지한다. iter_009의 공통 위치 불일치는 양성 134/200명이다. iter_012의 직접 SFT F1@0.3은 확인 양성 400명에서 세 seed 0.631–0.653이다. 이 사실은 다중 영상 대응 실패를 입증하지 않는다.
- iter_018 E48에서 범위 안내 후 순손실은 6.25 pp, 95% CI [−6.25, 18.75] pp다. F105 확대 보류를 유지한다. category별 사후 관찰로 주가설이나 기준을 바꾸지 않는다.
- iter_018 리뷰는 최초 결과·protocol 삭제와 cache 변경을 원본 보존 지시 위반으로 기록했다. 후속 구현에는 새 결과 경로와 append-only 실행 이력을 요구해야 한다. canonical 결과의 수치 검증과 삭제된 원본의 재현 여부를 구분한다.
- iter_003은 독립 단위가 3명이며 GT로 구성한 packet을 사용했다. context가 오류를 교정한 경우도 있었다. 가산 보정 실패를 모든 다중 영상 방법의 실패로 확대하지 않는다.
- iter_008 보완의 일회성 정상 사용 점검은 iter_009에서 수행됐다. 이를 처음부터 반복하지 않는다. 새 다중 영상 입력의 image-token 연결·순서·전처리·출력 규약은 별도로 검증해야 한다.

`context-sensitivity`는 관련된 observed 주장으로만 연결한다. 새 영상 대응 실패가 validated라는 뜻이 아니며, 현재 단계에서 method로 진입할 근거는 없다.

## Strategy Check / 연구 방향 판단

중요한 사용 과제는 여러 view·slice·시점에서 얻은 근거를 해당 영상·영역에 정확하게 연결하는 것이다. 단순한 입력 변화에 대한 답변 불변성보다, 필요한 정보 통합과 잘못된 연결을 구분하는 것이 목적이다.

### 1순위: 다중 영상 대응의 원인 진단

개별 영상 인식 실패와 영상 간 대응 실패를 구분하면 직접 SFT, 분리 실행, 대응 모듈 중 다음 투자를 선택할 수 있다. 새로운 공개 benchmark와 학습 baseline이 있어 처음부터 큰 자료를 만들 필요도 없다. 다만 기존 연구가 이미 강하며, 합성 차이 찾기나 입력 순서 민감성만 재현하면 기여 가치가 낮다. 실제 reference–target 관계와 유효한 GT가 있는 소수 과제를 먼저 확인한다.

### 다른 연구 질문: 실제 시간 변화 판단

중요성은 높지만 접근 가능한 longitudinal 영상의 확인이 먼저다. 기존 iter_018 round_02의 학습 원천 중복 우려를 이어받되, 이번에는 새 benchmark와 접근 조건이 대안을 바꾸는지 확인했다. 아래 MI-CXR도 MIMIC 접근을 요구하므로 공개 질문 파일만으로 실행 가능하다고 판단하지 않는다.

### 현재 grounding 방법 개선

강한 직접 SFT 자산과 잔여 오류는 있다. 그러나 추가 loss 두 후보와 좌표 전달 진단에서 후속 투자를 뒷받침할 근거가 부족했다. 다른 데이터에서의 일반화·효율 또는 모듈형 대안 대비 이점을 겨냥한 구체적 가설이 생기면 다시 비교한다. 이번 문헌 조사만으로 학습을 재개하지 않는다.

### 현재 범위 민감성 추가 진단

기존 실행 비용은 낮지만 정보 이득도 낮아졌다. 단일 질문에서는 무관 evidence 제외가 direct 입력과 같아진다. 관련 evidence를 실제로 유지해야 하는 과제와 공정한 질문별 분리 baseline을 제시하기 전에는 F, 문구 탐색, 새 loss를 추가하지 않는다.

### 답변 가능성·abstention

중요한 대안이지만 일반적인 과신·답변 거부 평가는 이미 CARES와 MedVH가 다룬다. 미주석이나 crop으로 제거된 영역을 곧바로 임상적 음성·답변 불가능 정답으로 만드는 설계도 부적절하다. 현재 확보한 자료에서 이 정답을 보장할 경로가 다중 영상 후보보다 명확하지 않아 후순위로 둔다. [CARES 연구진 페이지](https://cares-ai.github.io/), [MedVH 공식 자료](https://www.physionet.org/content/medvh/1.0.1/)

선택은 잠정적이다. 비용이 작다는 이유로 현재 진단을 연장하거나, 새로운 이름을 붙였다는 이유로 다중 영상 후보를 채택하지 않는다.

## 새 문헌·자료가 바꾼 설계 조건

### 시간 변화 자료: 공개 benchmark와 영상 접근은 별개

[MI-CXR 연구진 저장소](https://github.com/AIDASLab/MI-CXR)는 다섯 방문의 영상에 대한 사건 위치·구간 변화·전체 경과 질문을 제공한다. 약 5,311개 질문 파일이 있지만 영상은 MIMIC-CXR-JPG이며 MIMIC-Ext-CXR-QBA와 함께 credentialed access 조건을 명시한다. 표의 MedGemma-4B 결과를 MedGemma 1.5 revision의 성능으로 동일시할 근거는 확인하지 못했다.

[MS-CXR-T 공식 페이지](https://physionet.org/content/ms-cxr-t/1.0.0/)도 credential, 교육, DUA를 요구한다. 로컬의 파일명 기반 제한 검색에서는 해당 자료를 찾지 못했다. 이는 사용자의 자격이나 다른 저장 위치에 자료가 없다는 확정이 아니다. 공개 mirror로 접근 조건을 우회하지 않는다.

[MedGemma 1.5 기술 보고서 v1](https://arxiv.org/html/2604.05081v1)의 Table 1·2를 다시 확인했다. Chest ImaGenome sequential image·bbox 39,968개를 RL 자료로 기술하고 MS-CXR-T는 OOD로 표시하지 않는다. 기존 조사와 일치한다. 원천 중복을 test 환자 누수로 단정하지 않되 외부 일반화 주장에는 사용할 수 없다.

### MedSG-Bench: 접근 가능한 후보지만 임상 변화 정답을 자동 제공하지 않음

[NeurIPS 2025 공식 논문 페이지](https://proceedings.neurips.cc/paper_files/paper/2025/hash/6c22b0280d0d7d9e0c3126b1e92df1a0-Abstract-Datasets_and_Benchmarks_Track.html)에서 8개 과제와 MedSG-188K·MedSeq-Grounder를 확인했다. [연구진 배포](https://huggingface.co/datasets/MedSG-Bench/MedSG-Bench/tree/main)는 22.5 GB와 CC-BY-4.0 표기를 보여주지만, 개별 원천의 조건과 환자 분할까지 확인한 것은 아니다. viewer에는 JSON/PNG 처리 오류가 있어 자동 loader 성공을 가정할 수 없다.

과제 구성은 조회 가능한 [arXiv v1 §3.2](https://arxiv.org/html/2505.11852v1)에서 확인했다. Task 1은 원본에 국소 변형을 넣고 Task 2는 추가 위치 이동을 적용한다. Task 3·4에는 실제 view/video와 volume slice 구성이 섞인다. 따라서 합성 차이 탐지를 실제 시간 변화 판단으로 보고하면 안 된다. Task 8은 부분 주석의 모호성을 줄이려고 의미적으로 다른 후보 영상을 사용한다. 비슷한 임상 영상 사이의 혼동까지 검증하는 자료인지 추가 확인이 필요하다. 최종 PDF의 세부 본문 조회는 실패했으므로 v1 과제 설명을 최종본과 완전히 같다고 확정하지 않는다.

### 가까운 방법이 이미 있어 단순 다중 영상 SFT는 차별성이 부족함

[Migician, Findings ACL 2025](https://aclanthology.org/2025.findings-acl.512/)은 단일 영상 grounding과 다중 영상 이해의 결합 및 직접 다중 영상 grounding 학습을 다룬다. 따라서 분리 실행 자체나 multi-image SFT 자체를 새 방법으로 주장할 수 없다.

[Medical thinking with multiple images, ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/hash/a7060588538c3ca1ef2fb071db9e5630-Abstract-Conference.html)은 영상별 해석, cross-view evidence 통합, 단계별 평가를 명시한다. 이는 단순한 오류 분해조차 기존 연구와 대조해야 함을 보여준다. 이번에는 공식 초록만 확인했으며 자료 접근·주석·실험 세부는 미확인이다.

[GeM-VG](https://arxiv.org/abs/2601.04777)도 가까운 다중 영상 grounding 후보로 확인했다. 구체적 방법과 우리 후보의 차이는 다음 조사 대상이다. 이 문헌들을 모두 재현할 계획은 아니다. 실제 과제와 가장 가까운 baseline을 선택해야 한다.

## 잠정적으로 식별할 설명과 결과의 가치

다음은 확정 실험 행렬이 아니라 후보 선택에 필요한 구분이다.

- **영상별 인식 실패:** 개별 입력부터 틀리면 joint 저점수를 영상 간 연결 문제로 해석하지 않는다.
- **형식·순서 효과:** 명시적 영상 ID와 올바르게 갱신된 질문·정답으로 해소되는지 확인한다. 실제 시간축을 뒤집고 같은 정답을 유지하는 잘못된 불변성 검사는 하지 않는다.
- **영상 간 연결 실패:** 개별 인식 근거가 있는 조건에서도 joint 입력에서 소견을 다른 영상·영역에 연결하는 오류가 남는지 본다. 조건부 부분집합 점수와 전체 집단 점수를 함께 보고해야 한다.
- **통합의 실제 필요:** 단일 영상별 추론과 규칙·reader 결합으로 충분하면 이를 강한 실용 baseline으로 보존한다. 모든 원본 영상과 필요한 도구를 허용하고 호출 수·비용을 비교한다.

양성이면 정상 사용과 독립 자료에서 중요한 잔여 실패를 검증한 뒤, 직접 SFT 대비 새 조합 일반화·데이터 효율을 겨냥한 방법을 검토한다. 음성이면 단순 입력 보정 또는 분리 실행을 채택하고 내부 대응 학습의 투자를 낮춘다. 불확정이면 주석·입력 문제와 표본 정밀도를 구분한다. 정답이 불명확한 자료를 더 많이 생성해 해결하려 하지 않는다.

## 코드 재사용과 자원

`git -C research status --short`, `git diff`, `git ls-files`를 확인했고 작업 변경은 없었다. HEAD는 `4e453bbba4b0e798c0deeb6a940644dd62707fa3`다.

현재 `qa_gen.py`, `qa_protocol.py`와 `generate.py`의 입력 경로를 확인했다. `generate.py`는 한 영상의 chat 입력과 hash를 구성하고, QA record도 단일 영상 필드에 연결된다. 다중 영상은 파일 목록만 바꾸어 재사용할 수 없다. 영상 순서별 hash, image-token 대응, reference/target 연결을 검증해야 한다. `qa_protocol.py`의 과거 과제 전체 REQUIRED_CODE 의존과 데이터 잠금 미강제도 실제 선택 경로에서 해결해야 한다.

현재 승인된 parser·기하 유틸리티의 범위와 전체 실행기 승인을 구분한다. 새 접근법의 자동 기반에는 현재 RSNA 모듈이 없을 수 있다. 과제 확정 후 필요한 개별 파일·의존성과 실제 전체 SHA를 반입 목록으로 고정한다. 이번 `reuse_assets=[]`는 조사 중 미확정 상태이며 재구현 허가가 아니다.

iter_018 D16의 2/4 worker wall-clock은 60.40/60.51초로 이득이 거의 없었고, 4 worker GPU peak는 17,572/17,501 MiB였다. 이를 다중 영상 메모리나 긴 출력 비용으로 그대로 적용하지 않는다. 구현 계획에서는 두 GPU의 독립 shard를 사용하고 development에서 batch 확대 또는 GPU당 2 worker를 유망한 순서로 비교한다. 전체 처리량·출력 정합성·긴 출력 peak와 worker당 2GiB 여유로 선택한다. 표본·요청 행렬이 미정이므로 wall-clock을 지금 확정하지 않는다. 임의 시간 상한도 두지 않는다.

## 대규모 GPU 필요 후보

다중 view·slice·시점의 correspondence를 함께 학습하는 vision encoder–언어 모델 공동 post-training을 보존한다. MedSeq-Grounder의 보고된 학습은 4×A40 48GB를 사용한다. 이는 해당 전체 학습 구성의 비용이지 현재 두 GPU에서 진단이나 LoRA를 못 한다는 근거가 아니다. 실제 잔여 실패가 확인되면 frozen encoder 기반 모듈, 직접 LoRA, 공동 학습의 필요성을 비교한다.

## 한 라운드 더 필요한 이유

추가 확인은 후보 순위를 실제로 바꾼다. MedSG의 사용할 부분이 합성 변화에만 의존하면 temporal 후보에서 제외해야 한다. 환자·원천 연결이나 reference 정답이 없으면 독립 진단이 불가능하다. 가까운 방법이 이미 같은 실패 조건과 해결을 다룬다면 새 후보의 가치도 낮아진다. 이 세 가지와 최소 대조를 확인한 뒤 구현 여부를 결정한다.

새 방향의 긍정적 실험 근거는 아직 없으므로 이번 문헌은 조사 기록이며 사용자 논문 추천으로 추가하지 않는다.
