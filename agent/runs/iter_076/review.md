# Assessment

계획은 기술 복구 후 기존 F/R/C/H 비교 전체를 완료하도록 요구했다. 그러나 claude_report.md의 실질적인 보고는 ‘재개 검사 완료 알림을 기다린다’는 문장이다. claude_stream.jsonl의 최종 result 이후 재개 검사 작업과 대기 작업이 killed/stopped로 기록됐다. 정상 SDK 반환은 실험 완료를 뜻하지 않는다.

# Key Findings

1. `tests/fixtures_cpu.json`의 개별 검사 50개를 재집계해 50개 통과를 확인했다. `tests/gate_tamper.json`의 8개 변조 사례는 모두 비정상 종료했고 학습 로그와 checkpoint를 만들지 않았다. 실패 gate 재사용 차단은 유용한 개선이다.
2. 원시 train_log.jsonl에서 det_ref는 7 step, det_ref_g1은 6 step이다. 공통 6 step의 loss 최대 절대차를 독립 계산한 결과 0이었다. 두 실행의 코드 provenance도 현재 파일과 일치한다. 이는 장치 간 연속 실행의 부분 관찰이며 저장·복구 성공 증거가 아니다.
3. `freeze_start.json`은 비LoRA parameter 883개, 4,300,079,472개 원소, 8,600,158,944 bytes를 기록한다. 비LoRA requires_grad 및 optimizer 포함 수는 모두 0이다. 종료 digest와 실제 LoRA 변화의 최종 검증은 없다.
4. `resume_compare.json`, `freeze_check.json`, 본학습 디렉터리, 평가 디렉터리와 ledger.jsonl은 없다. 따라서 과학적 metric·CI를 독립 재계산할 새 출력도 없다.
5. 직전 리뷰의 ‘e3e19f4387647450은 빈 SHA256 prefix’라는 설명은 잘못이었다. 빈 입력 SHA256은 `e3b0c44298fc1c14…`다. 이 설명을 정정하며, update 전후 동결 검증 미완료라는 판단은 별도로 유지한다.

# Problems / Concerns

현재 결론을 막는 문제는 재개 검사 및 본실험 미완료다. 두 반복에서 같은 조기 종료가 발생했으므로 다음 구현은 코드 작성보다 실제 작업을 끝까지 관리하는 흐름을 먼저 고쳐야 한다. 로그의 seven_day 이벤트는 allowed_warning이며, 확인된 한도 거부로 이번 종료를 설명할 수 없다.

메모리 안전 여유도 부족했다. recovery_manifest.json은 GPU 총점유 24,027/24,576 MiB와 23,955/24,576 MiB를 기록한다. 두 기술 실행 로그에 allocator OOM 경고가 있고 peak allocated는 약 21.477 GiB다. 경고 이후 step 기록이 있으므로 이를 곧바로 최종 fatal OOM으로 단정하지 않지만, worker당 2GiB 여유 미충족은 명확하다. 리뷰 환경의 nvidia-smi는 드라이버에 접근하지 못했고 ps도 격리된 프로세스만 보여 현재 호스트 잔존 작업은 확정하지 못했다. 이 제한을 호스트 장애로 해석하지 않는다.

`sp75_resume_test.py`는 기존 BASE가 있으면 종료한다. 원 결과를 보존하는 것은 적절하지만 이번 중단 결과를 안전하게 이어갈 기능이 없다. 새 경로에서 처음부터 반복하는 대신 checkpoint와 완료 단계에 연결한 복구가 필요하다. `sp75_pipeline.py`의 메모리 검사도 기존 worker의 향후 peak와 여유 예약을 보장하지 않는다.

사전 lock과 사후 seal 분리, JSON 예측 중복·누락 검사 등은 구현됐으나 실제 전체 경로 검증이 없다. 해당 파일들을 검증된 기준점으로 승인하지 않는다.

# Interpretation

이 반복은 기술 복구 실패이며 가설 기각이 아니다. 인식 부족, 질문에 맞는 영역 선택, 위치 제한 supervision의 전이, 공유 분류기의 충분성 중 어느 설명도 새로 구분하지 못했다. 여러 영상 입력이나 기술 loss만으로 결합 능력을 주장할 수 없다.

OAI 중단 지시는 유지됐으며 새로운 OAI 확보나 MR-RATE 대기를 재개한 근거는 없다. 기존 결과·코드 보존과 현재 코드의 재사용 승인은 구분한다. 한계 주장 상태를 바꿀 새 과학적 증거는 없으므로 limitation_updates는 비운다.

# Strategy Check / 연구 방향 판단

- **실행 유효성:** 기술 검사 일부만 완료됐다. 과학적 비교는 유효 실험으로 세지 않는다.
- **성능 개선:** 본학습·E24 출력이 없어 미판정이다.
- **가설 지지:** 기존 위치 prior·인식 적응·대상 지정/해상도·공유 분류기 충분성의 경쟁 설명은 그대로 남는다.
- **신규 기여 가능성:** 이번 결과로 증가했다고 볼 근거가 없다.

iter_075/076의 방향 판단을 유지한다. 현재 지배적인 비용은 준비·실행 복구와 중단에 따른 재작업이며 정확한 GPU 누적 비용이나 비율은 산출하지 않았다. 새 자료나 다른 모델로 바꾸는 것보다 현재 준비된 비교를 완료하는 정보 가치가 높다. 타 계열 학습 보류도 유지하되 MedGemma 특이 현상이나 공통 현상으로 해석할 결과 자체가 아직 없음을 명시한다.

다음 투자는 한정 실행 복구 하나다. 복구가 통과하면 기존 비교를 수행하고, 실패하면 최초 불일치와 자원 원인을 특정해 해당 경로만 막는다. 진단 반복 횟수만으로 연구 질문을 기각하지 않는다.

# Recommended Next Experiment

새 실험 설계 없이 iter_075 기준 계획과 iter_076 복구 조건을 이어간다. 호스트 작업 확인 → 메모리 원인 및 안전 여유 확보 → 미완료 저장·복구/동결 검사 → 원 본학습·선택·평가·비용·독립 재계산 순서로 완료한다. 동일 provenance의 완료 검사는 반복하지 않는다. 구현 세션은 실제 자식 작업이 끝나기 전에 완료 응답을 내지 않아야 한다.

실행 실패이며 후속 방향의 유망성을 확인한 새 결과가 없어 논문 추천과 마일스톤은 보류한다.
