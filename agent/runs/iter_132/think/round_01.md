# 사고 라운드 1

## 핵심

기존 두 후보의 보류를 유지한다. 새 후보로 **실제 반복 촬영 MRI에서 사용할 영상의 품질을 비교하는 능력**을 찾았다. 공개 전문가 정답과 강한 단순 대조가 존재한다는 구체적 근거가 있어 즉시 탐색 범위를 사용자에게 돌리지는 않는다. 다만 원 점수 파일과 영상 연결, 가까운 선행 이후의 판별 질문을 아직 확정하지 못했으므로 구현을 발주하지 않는다.

## 원 기록에서 유지할 판단

- `agent/GOAL.md`, `agent/runs/iter_131/review.md`와 `plan.json`, `iter_131/think/round_01.json`, `iter_130/review.md`, `iter_129/review.md`, 관련 `LIMITATIONS.md`와 `INDEX.md` 항목을 확인했다.
- iter_131은 기록 작업이며 새 유효 실험이 아니다. 최소 직접 적응과 불완전 sequence 보존 후보를 다른 이름으로 재개하지 않는다.
- iter_129의 T2 개발40명 전원 PRESENT·BA0.50은 정상 사용 검사를 거친 제한적 관찰이다. 정규화 단독 회복은 지지되지 않았으나 기본 인식·관측 충분성·질문 영향은 미분리다.
- iter_130의 L2.4 258행·187환자·197study는 동일 병변의 sequence별 정답을 보장하지 못했다. 자료 감사를 다시 실행할 이유는 없다.
- `iter_124/review.json`의 사용법 검사·한계 범위·code_assets를 확인했다. FLAIR23명의 두 모델 고정 응답은 품질 판별 실패의 증거가 아니다.
- 상대 비교와 관련된 `iter_054/review.md`도 확인했다. 과거 자연 영상쌍의 상대 신호를 실용적인 단일 영상 방법으로 옮길 경로는 미확정이었다. 새 후보에서는 실제 반복 촬영 선택이라는 사용 조건이 필요한 이유다. 과거 결과를 MR-ART의 양성 근거로 쓰지 않는다.

## 새로 확인한 자료 조건

[MR-ART 공식 저장소](https://github.com/OpenNeuroDatasets/ds004173)는 건강한 성인148명의 T1w MRI와 사람별 세 촬영 조건, MRIQC 산출물 및 neuroradiologist 품질 점수를 제공한다고 명시한다. [공식 dataset_description.json](https://raw.githubusercontent.com/OpenNeuroDatasets/ds004173/main/dataset_description.json)에서 CC0와 dataset DOI `10.18112/openneuro.ds004173.v1.0.2`를 확인했다. 이번에 영상이나 원 점수 파일을 확보한 것은 아니다.

[MRIQC 개발 측의 MR-ART 분석 예제](https://www.nipreps.org/qc-book/auto-qc/iqms_interpretability.html)는 `scores.tsv`의 `bids_name`과 `score`, `IQMs.tsv`의 같은 식별자로 연결하는 코드를 제시한다. 점수는 전문가가 조정한 good/medium/bad의 세 등급이며, 촬영 조건과 일치하지 않는 사례가 있다. 예제 표에는 `sub-000103`의 세 촬영에 2/3/1 점수가 연결돼 있다. 이는 schema와 연결 가능성의 단서이며 원 배포 파일을 검산한 결과는 아니다. **움직임 지시·파일명으로 품질 정답을 만들면 안 된다.** 예제에서 본 사례는 향후 미노출 확인 사례로 취급하지 않는다.

현재 확인한 MR-RATE 보고서·병리 라벨 schema는 이 전문가 품질 정답을 대신하지 않는다. 따라서 이 후보는 MR-RATE 질병 판별의 연장이 아니라, MRI 관측 활용이라는 상위 질문 안에서의 자료·과제 변경 후보다. MR-RATE 결과와 직접 합산하거나 새 후보가 그 원인을 설명한다고 주장하지 않는다.

## 가까운 선행과 해석

[MMRQA 원문](https://arxiv.org/html/2509.24888v1)의 Methods·평가를 읽었다. MRQy 지표를 언어 QA로 바꾸고 LLaVA-OneVision을 LoRA 적응하며 MR-ART를 평가한다. 따라서 지표를 VLM에 넣거나 품질 등급을 학습하는 것 자체는 새 기여가 아니다. 설명 평가는 GPT-5를 사용하므로 이를 우리 임상 정답으로 채택하지 않는다. 이번 조회에서 재현용 checkpoint·분할 파일을 확인하지 못했으며 비공개라고 확정하지 않는다. 논문의 성능 주장은 우리 조건에서 재현한 사실이 아니다.

[Reliable Evaluation of MRI Motion Correction 원문](https://arxiv.org/html/2506.05975v1)의 평가·기전 설명을 확인했다. 이 연구는 별도 참고 촬영의 불완전성, 실제 손상과 합성 손상의 차이, reference-free VLM 점수의 과도한 평활화 선호를 다루며 MoMRISim을 제시한다. 따라서 '깨끗해 보임'을 해부학 보존 또는 진단 정확성과 동일시할 수 없다. 우리 후보에서 MR-ART의 세 등급만으로 재구성의 해부학 보존까지 주장해서는 안 된다. OpenReview PDF는 browser challenge로 열지 못했으므로 이 조사 근거는 확인한 arXiv 원문에 한정한다.

선행의 존재는 품질 문제가 모두 해결됐다는 증거가 아니다. 반대로 선행에서 VLM 실패를 보고했다는 이유만으로 MedGemma의 새 observed 한계를 만들 수 없다. 이번에는 논문 추천을 하지 않는다.

## Strategy Check / 연구 방향 판단

출처는 iter_131 리뷰 카드다. 바뀐 근거는 보고서 추출 라벨과 별개인 실제 반복 촬영·전문가 품질 점수의 존재와 가까운 품질 평가 선행이다.

1. 중요한 문제: 여러 MRI 관측 중 실제로 사용할 수 있는 영상을 고르는 능력이다. 질병 맞히기 점수와 구분한다.
2. 현재 근거: MR-RATE 고정 응답은 실제 관찰이다. MR-ART의 자료 구조와 선행 결과는 외부 근거이며 우리 모델의 품질 판별은 미실행이다.
3. 쉬운 해결책: MRIQC 지표·그 지표로 학습한 분류기, 독립 품질 등급의 순위가 우선 대조다. 같은 사람의 정상 촬영을 항상 정답 참고영상으로 제공하는 비실용 oracle는 피한다.
4. 남은 설명: 절대 등급 보정 부족, 손상 인식 부족, 직접 비교의 순서 편향을 구분해야 한다. 전문가 동점은 비교 실패나 임의 승패로 바꾸지 않는다.
5. 다음 결정: 원 정답·영상 연결과 강한 대조가 성립하면 작은 실제 비교 하나를 계획한다. 성립하지 않으면 후보를 보류하고 기록만 만드는 구현 반복은 금지한다.

## 대안 비교

- 반복 촬영의 상대 품질 판별: 새 후보 중 우선 확인한다. 실제 품질 정답과 단순 대조가 있다는 장점이 있다. 상대 비교의 실용 가치와 선행 이후의 잔여 질문은 아직 미확정이다.
- 기존 MR-RATE 최소 적응: 원 관찰과 직접 연결되지만 iter_131의 재개 조건을 충족하는 새 근거가 없다. 보류 유지.
- 현재 MRI 투자 보류·탐색 범위 선택 요청: 품질 후보까지 구체화하지 못하면 선택한다. 승인된 MRI 탐색 전체가 소진됐다고 단정하지 않고, 추가 정답 확보를 우선할지 다른 탐색 범위를 택할지 사용자 가치 선택을 명시한다.

## 확인하지 못한 것과 접근 오류

원 저장소 루트의 `scores.tsv` 추정 경로는404였다. 이를 자료 부재로 해석하지 않는다. GitHub derivatives 조회도 웹 도구에서 실패했고, shell의 GitHub API read-only 조회는 DNS 오류로 실패했다. 원 점수 위치·영상별 byte 크기·실제 적격 수는 아직 확인하지 못했다. 이 계획 환경의 오류를 구현 담당의 다운로드 불가나 추가 권한 필요로 확대하지 않는다.

## 코드·자원

`agent/CODE_ASSETS.md`의 iter_129 항목과 원 review.json/code_assets, 보존 SHA `4682b4bacadbaf12cf0f379f41a5a4fb1b9cb983`의 `mr123_data.py`, `mr128_gen.py`를 확인했다. 현재 연구 브랜치의 파일 목록도 조회했다. 렌더러 승인은 기존 NIfTI·mask 조건에 한정하며 실행기는 고정8장·MR-RATE 경로·계약 의존성이 있다. 새 품질 과제에 그대로 승인할 수 없다. `mr128_run.py`라는 추정 경로는 없었고 실제 파일명 `mr128_gen.py`를 확인했다. 코드 소실로 판단하거나 대체 구현을 발주하지 않았다.

아직 반입 모듈을 선택하지 않았으므로 reuse_assets는 비어 있다. 실제 비교를 선택하면 필요한 소스·의존성만 명시하고 두 GPU의 batch 또는 복수 worker 처리량·메모리·출력 정합성을 확인한다. 기존 8장 추론 처리량을 새 비교의 실측으로 쓰지 않는다. GPU 회피나 시간 상한 때문에 실행을 보류한 것은 아니다.

## 대규모 GPU 필요 후보

여러 MRI 획득 조건과 실제 손상을 포함한 3D 표현·언어 공동 적응은 장기 후보로 보존한다. 현재 두 GPU의 경량 적응을 금지하거나 대규모 학습이 필수라고 판단한 것은 아니다.
