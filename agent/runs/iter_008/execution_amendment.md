# iter_008 재개 보완 지시

사용자 의도를 반영한 운영 보완이다. 기존 plan.md·plan.json·과거 결과를 덮어쓰지 않는다.
연구 목표는 유지하고 `agent/RESEARCH_POLICY.md`, `agent/RESOURCE_POLICY.md`를 우선 적용한다.

## 코드 재사용

`code_recovery.md`의 iter_007 원본 11개 파일을 현재 research/ 브랜치에 복구했다.
복구 자체는 검증 승인이 아니다. 원 계획의 완료 판정·provenance·CUDA 가시성 결함을 먼저
수정하고 실패 입력 회귀 검사를 수행한다. 기존 자산을 확인 없이 재작성하지 않는다.
이번 실험과 무관한 인프라 개선으로 범위를 넓히지 않는다.

## 연구 목표와의 연결

- 이번 frozen-head 실험은 diagnostic이다. 독립적인 novelty나 VLM 개선의 증명이 아니다.
- 실행 전에 research/notes/에 재현할 가장 가까운 baseline, 이번 진단의 정보 이득,
  다음 실제 MedGemma grounding 출력 과제·출력 형식·데이터·metric·진입/중단 조건을 정리한다.
  head와 실제 출력은 공통 입력·target·metric으로 비교 가능한 범위를 명시하고,
  제한된 GPU에서 가능한 adapter/LoRA 등 후속 후보와 직접 적응 baseline을 연결한다.
- 단순히 진단만 반복하지 않는다. 다음 계획에서는 실제 출력 baseline 또는 방법 개발로
  넘어갈지를 이번 결과로 결정한다. head 실패를 경량 학습 전체의 실패로 일반화하지 않는다.

## 자원과 학습 유효성

- 기존 45 device-minute 상한은 폐기한다. 두 24GB GPU의 허용 범위·실측 메모리·처리량에 맞춰
  필요한 본실험을 수행한다. 현재 입력에 명시된 timeout과 타인 프로세스 보호는 유지한다.
- 원 계획의 학습 budget·LR은 시작점이다. train/validation에서 학습 curve와 수렴을 확인한다.
  baseline이 미수렴이면 독립 확인 자료를 열기 전에 대칭적인 budget 확장 등 보완을 정하고
  변경 이유·조건·판정 기준을 실행 manifest에 먼저 남긴다.
- 기존 48명 결과는 개발 자료이며 새 독립 test로 부르지 않는다. 신규 확인 집단의 분리와
  사전 동결을 유지한다. 확인 결과를 본 뒤 threshold·학습량을 바꿔 같은 집단에 재도전하지 않는다.
- 원 계획의 데이터 접근·누출 방지·대조군·지표 기준은 유지한다. 실행 오류, 불충분한 학습,
  정밀도 부족을 구분하고, 결과를 본 뒤 성공 기준을 완화하지 않는다.

## 보고·리뷰

현재 결론을 무효화하는 결함, 재사용 전에 고칠 결함, 추후 개선을 분리한다.
실행 실패를 가설 실패로 판정하지 않는다. 유효한 음성 결과의 구현도 보존 가치를 판단한다.
기존 계획의 오래된 JSON에 새 필드가 없더라도 위 보완 지시를 적용한다.
