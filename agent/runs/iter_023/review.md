# Problems / Concerns

현재 결론을 막는 핵심은 사분면 QA 비교 자체의 부재다. 표본이 작아 불확정인 결과가 나온 상황과 구분해야 한다.

재사용 전에는 다음 결함을 해결해야 한다. 첫째, pipeline 문서와 달리 단계별 decision이 실행을 제한하지 않는다. E 요청을 직접 만들고 실행할 수 있으며 D gate·확대 조건을 강제하는 경로가 없다. 둘째, protocol의 필수 데이터 목록이 stage별로 고정되지 않아 extra 누락을 거부하지 못한다. 셋째, 평가가 현재 protocol 대신 출력의 digest를 신뢰하고 completion의 모든 연결 정보를 재검증하지 않는다. 요청 파일 자체가 불완전해도 manifest 기준 예상 행렬과 비교하지 않는다. 넷째, bbox source를 읽는 경로는 출처 잠금·완료·중복 검증이 부족하다.

형식 fallback 전달, strict 지표와 환자별 상세 저장, 전체 요청 기준 oracle 정확도 및 퇴화 bootstrap의 대체 차이 구간도 미완성이다. 현재 코드에서 CP 비율 구간을 출력하는 것만으로 사전 판정 규칙이 구현됐다고 볼 수 없다.

공식 입력 대조·실제 재개·완료 후 변조 거부·동일 입력의 worker 비교 완료 근거도 확인하지 못했다. 반입 manifest는 여전히 pending_validation이며 전체 스냅샷 재사용을 승인하지 않는다. 기본 사분면 규칙과 parser 모듈은 저장된 관련 검사 범위에서 별도 승인한다.
