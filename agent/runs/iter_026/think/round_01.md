# 사고 라운드 1

## 새로 확인한 것

이번 라운드는 문서·소스·문헌 조회, adapter 파일 hash 확인, 저장된 주석과 생성 출력의 읽기 전용 재집계만 수행했다. 파일 생성·수정, 모델 로딩, 학습·추론·테스트 실행은 하지 않았다.

### 1. 기존 성과와 적용 범위

`agent/GOAL.md`, `agent/REPORTING_STYLE.md`, `agent/LIMITATIONS.md`, `agent/CODE_ASSETS.md`, iter_009·025 리뷰, iter_012–018의 원본 계획·리뷰 주요 부분, iter_025 계획·조사 기록을 대조했다.

- 이미 확인: iter_012의 직접 RSNA SFT bbox 개선은 유효하다. iter_013–014의 특정 추가 loss 결과는 이 성과를 기각하지 않는다.
- 이미 확인: iter_015–016은 전역 QA의 큰 형식 효과를, iter_017은 검출·개수·좌표 전달 효과를 구분했다. 이 질문들을 이름만 바꾸어 반복하지 않는다.
- 아직 미확인: 위치에 따라 정답이 달라지는 미학습 질의에서 SFT가 같은 영상의 공간 정보를 활용하는가.
- 유지: 사용자 보완의 RSNA checkpoint 진단 우선순위, 기존 성과·분할·원시 출력.
- 종료·보류: 현 사분면 yes/no prompt 탐색과 기존 E 진입 경로는 종료한다. 새 학습·loss, MRI F139, reserve와 longitudinal 전환은 보류한다.

iter_025 리뷰에 따르면 thinking marker 처리 누락은 M0 OB-T 24건과 OC-T 3건에 영향을 준다. marker 뒤 정답을 모두 반영해도 해당 oracle의 90% 기준을 충족하지 못한다. 과거 점수와 gate는 보존하고 보정 분석은 별도 개발 기록으로 남겨야 한다. AR 성공은 답 읽기 sanity이며 산술 단일 원인이나 시각 전이의 증거가 아니다.

### 2. 영역 선택을 실제로 요구하는 표본 수

`research/results/iter_023/manifests/{sets,labels}.json`의 원본 bbox 중심으로 TL/TR/BL/BR를 독립 재계산했다. 모든 환자에게 네 질의를 적용했을 때의 분포다.

| 집단 | 환자 수 | 여러 사분면에 주석이 있는 환자 | 빈 정답 질의 | 전체 목록이 정답인 질의 | 비어 있지 않은 진부분집합 질의 |
|---|---:|---:|---:|---:|---:|
| D24 primary | 24 | 14 | 57 | 10 | 29 |
| E60 primary | 48 | 22 | 120 | 26 | 46 |
| E200 primary | 160 | 66 | 410 | 94 | 136 |
| E200 boundary | 40 | 24 | 95 | 16 | 49 |

기존 계획의 E200 primary 66명과 빈 정답 64.06%를 재확인했다. 이 수치를 새 발견으로 취급하지 않는다. 새 의미는 평가 단위의 선택이다. 질의별 정확도를 그대로 평균하면 빈 목록이 유리하고, 비어 있지 않은 정답만 평균하면 전체 목록 복사의 부분 점수를 과대평가할 수 있다. 환자 내 네 질의를 함께 평가하고 진부분집합 집단을 별도로 보고할 필요가 있다. boundary 환자는 삭제하지 않고 별도 결과로 유지해야 한다.

D24의 진부분집합 환자는 14명뿐이다. D 성공이나 실패를 모집단 선택 능력의 확정 판정으로 쓰기 어렵다. E60 primary의 해당 환자도 22명이므로, 작은 차이의 불확정을 곧바로 전이 부재로 해석해서는 안 된다.

### 3. 새로 확인한 핵심 함정: 검출 개선만으로도 전이처럼 보일 수 있다

`results/iter_012/confirm_base/gen_worker*.jsonl`과 `confirm_sft_seed17/gen_worker*.jsonl`을 기존 개발 E 집단에 연결해 재집계했다. 새 모델 출력은 생성하지 않았다.

평가 설계 후보로 다음 영역별 F1을 계산했다. GT를 중심 사분면에 배정하고, 각 질의에서 예측 중심도 요청 사분면에 속하면서 IoU≥0.3인 경우에만 일대일 matching한다. 네 질의의 TP·예측 수·GT 수를 환자 안에서 합쳐 F1을 계산한 뒤 환자 평균을 구한다. 요청 밖 예측도 FP 분모에 남긴다. invalid 환자는 0점이다. 이는 새 주지표의 확정이나 과거 metric의 변경이 아니라, 대조군의 식별력을 확인하기 위한 개발 분석이다.

| 기존 출력 | E200 primary 160명: bbox+규칙 | 같은 전체 bbox를 네 질의에 복사 | 진부분집합 66명: bbox+규칙 | 같은 전체 bbox 복사 |
|---|---:|---:|---:|---:|
| M0 concise | 0.033333 | 0.011944 | 0.030303 | 0.012121 |
| M0 official_long | 0.093750 | 0.040000 | 0.060606 | 0.030303 |
| B0 concise | 0.542292 | 0.219248 | 0.647980 | 0.274944 |

E60 primary 48명에서도 B0 규칙/복사는 0.677083/0.273545, M0 official_long은 0.069444/0.030556이었다. E60과 E200의 차이를 모델 변화로 해석하지 않는다. 집단 구성이 다르다.

E200 primary에서 M0 concise는 valid_nonempty 146명, valid_empty 10명, truncated 4명이다. official_long은 160명 모두 valid_nonempty, B0는 valid_nonempty 129명과 valid_empty 31명이다. 독립 파싱의 실패 분류를 기존 `parse.py`로 대조했으며 M0의 네 실패는 실제 truncated였다.

중요한 결론은 B0 전체 복사 0.219248이 M0 official_long+규칙 0.093750보다 높다는 것이다. 따라서 직접 B0가 M0보다 좋다는 결과만으로 새로운 질문을 이해했다고 주장할 수 없다. 각 모델의 질의 무시 baseline과 질의 조건부 출력을 비교해야 한다. 위 수치는 실제 선택 출력의 성능이나 전이 효과가 아니다.

이 평가 후보는 빈 목록의 평균 점수 부풀림을 줄인다. 완벽한 GT 목록을 네 질의에 그대로 복사하면 환자별 F1은 0.4, 올바르게 분할하면 1이다. 그러나 직접 생성에서 검출·좌표 자체가 달라질 수 있으므로, 이 지표만으로 선택 능력의 순수한 인과 효과까지 식별하지는 못한다. 이 부분을 다음 라운드에서 확정해야 한다.

### 4. 가까운 선행 방법과 차별성의 범위

[Targeted Visual Prompting](https://arxiv.org/html/2408.03043v1)의 baseline과 논의를 다시 확인했다. 재확인 목적은 숫자 영역 입력과 시각적 영역 입력의 차이가 이미 다뤄졌는지 확인하는 것이다. 이 연구는 Region in text, Draw region, Crop region, Context only 등을 비교하고, 영역 위치·크기와 정답 사이의 상관이 평가를 쉽게 만들 수 있음을 논의한다. 따라서 영역을 표시하거나 crop을 붙이는 것 자체는 새 기여가 아니다. 현재 고정된 네 영역을 모든 환자에게 제시하는 설계는 GT에 맞춰 질의를 고르는 누수를 줄이는 데 유리하다.

새로 확인한 가까운 선행은 [CURE 원문](https://arxiv.org/html/2601.15408v1)과 [공식 프로젝트](https://pablomessina.github.io/cure-project-page/)다. CURE는 MedGemma 기반으로 phrase grounding, grounded report generation, anatomy-grounded report generation을 학습하며 Locate·Describe·Locate and Describe를 명시적으로 가르친다. 따라서 후속에 grounding과 영역 질의를 함께 학습시키는 것만으로 신규성을 주장할 수 없다. 반면 이 논문의 명시적 다중 과제 학습은 현재 bbox-only SFT의 미학습 질의 전이를 곧바로 답하지 않는다. 이는 과제·학습 조건을 비교한 해석이며 문헌 전체에 해당 진단이 전무하다는 주장은 아니다.

CURE의 모델 표기는 MedGemma-4B-IT이며 현재 MedGemma 1.5와 동일 모델로 취급하지 않는다. 문헌은 비교 설계의 근거로 기록하며, 이번 새 GPU 실험의 긍정적 결과가 없으므로 사용자 논문 추천으로 올리지 않는다.

### 5. 실제 재사용 상태

현재 `research/` HEAD는 `89b2975a679c6eed3d9a356d2c01d85b7950a1bf`다. `git status --short`와 `git diff --stat`는 비어 있다. 필요한 `roi23_*`, `roi25_*`, `parse.py`, 모델·adapter 관련 소스는 현재 브랜치에 있다. 현재 접근법의 RSNA 전이 질문을 이어간다면 별도 선별 반입은 필요하지 않다. 새로운 세부 인터페이스는 새 결과 경로와 spec으로 구분해야 한다.

adapter 파일 SHA256을 이번 라운드에서 다시 계산해 기존 기록과 일치함을 확인했다.

- B0: `results/iter_012/train/lr2e-4_s17/epoch_05/adapter.pt` — `5f542af96df705e567bf4cfb000398b09313db2456c577e772bd76481799cf29`.
- B29: `results/iter_012/train/lr2e-4_s29/epoch_05/adapter.pt` — `d4db2f2ab10d134b4352c7f57cc0ca5c497da3bce388d9cc91751ec9ca6d1fc9`.
- B43: `results/iter_012/train/lr2e-4_s43/epoch_05/adapter.pt` — `e6e4730add1d942c81fb89aabd5477a779668d2f0f8ef01cc21af33032584f4a`.

파일 hash 일치는 실제 adapter 로드나 tensor digest 검증을 대신하지 않는다. 해당 실행 검증은 구현 단계에 남아 있다.

기존 bbox `parse.py`는 완결된 thinking marker 뒤 최종 JSON을 처리한다. yes/no parser의 누락을 bbox 경로에 그대로 일반화할 필요는 없다. 다만 새 출력 규약에서 동일 parser를 고정하고 애매한 여러 목록·잘린 출력·잘못된 좌표를 구제하지 않는지 확인해야 한다.

재사용 전 필요한 수정은 iter_025 리뷰의 실제 실행 경로에 한정한다. 공식 messages와 실제 입력 tensor 동등성, source·adapter·선행 decision 잠금, manifest에서 독립 재구성한 예상 요청 행렬, 완료·재개 시 현재 provenance 검증, 24요청 중단·재개 검사다. 과거 D protocol의 AR 함수 추가에 따른 hash 차이는 원본을 바꾸지 않고 호환 기록으로 연결한다. 미사용 MRI·학습 실행기 전면 정비는 제외한다.

### 6. 전략 판단과 다음 조사 가치

현재 방법 개선 / 기존 checkpoint 진단 / 다른 질문 전환을 비교했다. 추가 grounding loss는 복사와 선택 능력을 구분하지 못한다. 같은 yes/no 표현의 추가 탐색은 직전 결과상 정보 이득이 낮다. 다른 임상 과제로 즉시 전환할 근거도 아직 부족하다. 학습된 bbox 출력을 유지하는 영역 선택을 1순위로 좁히되, 단순 B0−M0 차이를 전이로 오인하지 않는 설계를 먼저 확정한다.

이번 think_more는 같은 문헌·질문을 반복하기 위한 선택이 아니다. 새 재집계에서 드러난 복사 baseline의 강도가 성공 기준을 바꾼다. 다음 라운드는 주지표·대조군, oracle의 해석 범위, 유효 표본과 확대 규칙을 확정하는 데 한정한다. 이 질문이 해결되면 구현 계획으로 넘어간다.

두 GPU 활용은 유지한다. iter_025의 pilot은 동일 작업량 비교가 아니므로 다음 실행에서는 같은 개발 요청으로 2/4 worker 또는 batch 확대를 비교해야 한다. 실측 peak에 worker당 2GiB 여유를 더하고 로딩 포함 처리량·긴 출력·정합성을 확인한다. 현재 조사에서는 새 처리량이나 wall-clock을 측정하지 않았다.

## 대규모 GPU 필요 후보

영역 질의·grounding·일반 QA를 결합한 vision encoder–언어 모델 공동 post-training을 후보로 보존한다. 필요성과 기여는 미확정이다. CURE는 원문상 단일 48GB RTX A6000에서 4-bit NF4·LoRA를 사용해 총 9,000 steps, 약 45시간 학습했다. 이 보고를 24GB 두 장에서의 불가능성이나 모든 경량 학습의 금지로 해석하지 않는다. 동일 규모 재현과 현재 자원에 맞춘 적응은 별도 실측이 필요하다.
