# Key Findings

1. `correction_iter073.md`는 통합 label의 test 환자 대응 1,957행 노출, 전체 key·중복·충돌 집계, 정규 audit 밖 임시 조회를 기록했다. 이 수치는 기존 리뷰 근거를 인용한 것이며 이번에 test grade를 재집계한 결과가 아니다.
2. 결측→0 치환의 원인 단정과 임상 정답 약 95% 일치 표현을 철회했다. `unique`는 원 행 하나가 아니라 유효 후보 값 하나로 정정했다. 기존 train/val prior와 원본 기록은 유지했다.
3. `load_moaks`와 `--original-label-link`는 읽기 전에 거부한다. main은 허용 입력의 manifest·revision·bytes·SHA256을 검사하고 원 label 연결을 명시적으로 보류한다. 금지 파일을 먼저 파싱하고 필터하는 기존 경로는 제거됐다.
4. 저장된 검사 항목을 독립 집계한 결과 run1은 62/63, 수정 후 run2는 63/63이었다. 실행 로그에서도 두 실행과 실패 수정, fetch 검증 완료를 확인했다. run2 wall-clock은 11.58초, 별도 입력 hash 검증은 2.61초다. 이는 전체 구현 비용이 아니다.
5. 리뷰에서 허용 파일 12개의 hash와 pinned manifest hash를 독립 재계산해 일치를 확인했다. iter_073 산출물 26개도 before 기록과 모두 같았다. 소스·fixture·로그를 검토했으며 파일을 쓰는 전체 시험은 리뷰에서 재실행하지 않았다.

# Problems / Concerns

현재 정정 완료 결론을 무효화하는 blocker는 없다. iter_073의 과거 blocking 판정은 원 기록에 유지되며 이번 정정이 과거 실행을 소급 승인하지 않는다.

`link_original`에는 공식 근거가 없는 mapping이 남아 있다. 현재 main에서 호출하지 않으므로 이번 완료를 막지는 않지만, 원 label 연결 경로는 재사용 승인에서 제외한다. `attrs['scope']`와 hash 일치는 독립적인 split 안전성 증명이 아니다. 직접 helper 호출은 main의 provenance 검사를 자동 상속하지 않는다.

출력 경로·덮어쓰기 검사는 현재 실행을 보호한 범위보다 넓은 보장을 제공하지 않는다. 새 경로로 확장할 때 보완하되 이를 이유로 지금 별도 준비 반복을 만들 필요는 없다.

# Interpretation

이번에 확보한 것은 신뢰할 수 있는 준비 기록과 제한된 코드 재사용 경계다. 인식 부족, 필요한 근거의 선택 실패, 상보 근거의 결합 실패 중 어느 설명도 이번 결과로 구분하지 않았다. 타 계열 모델 비교와 강한 기존 방법의 충분성도 미검증이다.

GPU·모델 요청이 없는 것은 계획과 사용자 대기 지시에 부합한다. 실제 영상 없이 GPU 실험이나 방법 학습을 시작할 근거는 없다. 논문 추천은 실제 모델 효과나 재현되는 진단 근거가 추가되지 않아 보류한다.
