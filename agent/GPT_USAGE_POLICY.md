# GPT 사용량 정책 — 중복 작업 절감, 판단·검증 유지

사용자 승인: 2026-09-29. 문맥·사고 라운드·보완 작업의 중복을 줄인다.
모델 변경은 추후 판단한다. GPT 모델은 gpt-6-astra로 유지한다.

## 계획 사고 등급 (2026-10-01 사용자 승인: deep 분리)

- 계획은 deep_medium=Astra/medium, deep_high=Astra/high, normal/light=Astra/low다.
  모델은 모두 gpt-6-astra다. normal과 light는 effort가 같아도 기존 작업 분류는 유지한다.
- deep_medium은 깊은 검토의 기본이다. 현재 연구 안의 경쟁 가설·진단 실험·문헌 검토·한정된
  결과 해석을 담당한다. normal/light는 승인된 방향의 명확한 보완·재실행·일반 후속 계획이다.
- deep_high는 연구 방향의 유지·중단·전환, 핵심 contribution 선정, 기존 핵심 해석을 뒤집는
  복잡한 판단에 쓴다. 작은 후속 질문의 선택을 연구 방향 전환으로 부풀리지 않는다.
  문헌 검색·새 실험·막연한 불확실성·사용자 보완/재계획 자체는 high 사유가 아니다.
- high 자동 선택에는 scope(research_direction/core_contribution/foundational_interpretation),
  decision(결정할 선택), difficulty(충돌 근거·어려운 해석), impact(오판의 연구·투자 영향)를
  모두 기록한다. 빈 근거·비전략 범위면 medium에서 확인하며 실험 실패로 처리하지 않는다.
  세 근거의 존재 검사는 최소 요건이고, 내용의 타당성은 리뷰에서 판단한다.
- 직전 리뷰의 next_plan_tier/next_plan_reason으로 바로 적절한 등급을 고른다. 명백한 전략
  판단을 medium으로 한 번 더 돌린 뒤 high로 반복하지 않는다. 추가 분류 전용 모델 호출은 없다.
- think_more의 next_think_tier/next_think_reason으로 다음 라운드 등급을 정한다. medium에서
  중요한 해석 충돌이 발견되면 남은 판단만 high로 넘긴다. high에서 방향이 정해졌으면 세부
  설계는 medium으로 낮춘다. 기존 조사·출처·노트를 버리거나 동일 문헌을 다시 전수 조사하지 않는다.
- 매 라운드 선택·근거·모델·effort는 think/round_NN.tier.json과 events.jsonl에 남긴다.
  tiers_used.json의 plan은 마지막 라운드 등급이며 혼합 사용은 라운드 기록·원본 로그로 확인한다.
  중단된 같은 라운드의 선택은 보존한다. 선택 변경을 위한 재실행·추가 라운드는 만들지 않는다.
- 첫 목표·사용자 보완·옛 deep 추천·추천 누락은 기본 medium에서 관련 맥락을 확인한다.
  중요한 전략 결정이면 다음 라운드 high를 요청할 수 있다. 옛 기록·계획을 다시 쓰지 않는다.
- --plan-tier는 계획만 명시적으로 고정한다. 기존 --gpt-tier는 계획/리뷰 모두 고정하며
  계획에서는 --plan-tier가 우선이다. 명시적 --gpt-tier deep는 high를 유지한다.

## 리뷰·구현·적용 경계

- 구현 standard/heavy의 GPT 리뷰는 normal/low, creative는 deep/high, light는 light/low다.
  Claude/Codex 중 누가 구현해도 동일하며, 명시한 --gpt-tier는 기존처럼 우선한다.
- deep는 기존 리뷰와 CLI·과거 기록 호환용 high 설정으로 보존한다. 새 자동 계획은 분리 등급을 쓴다.
- 구현 등급·필수 full 리뷰·독립 수치 검증·사고 라운드 상한은 변경하지 않는다.
  low는 필수 조사나 검증을 생략해도 된다는 뜻이 아니다.
- effort 값은 agent/tiers.json에서 매 호출 읽지만 이번 선택 로직 변경은 새 프로세스에서 적용된다.
  실행 중인 호출·GPU 실험은 유지하고 안전한 단계 경계에서 관리 프로세스를 재개한다.
  기존 계획·세션·결과·판정 기준을 보존하며 GOAL 변경·reset/replan은 필요하지 않다.
- high 비율에 강제 상한을 두지 않는다. 이후 5~10회 반복의 선택 근거·라운드 수·계획 수정/
  재작업·표시 토큰을 관찰한다. 절감률이나 품질 동등성을 미리 보장하지 않는다.

## 문맥과 출처

- 입력의 접근법·자산·한계 목록은 탐색용 색인이다. 전체 기록은 원본 경로에 보존한다.
  현재 GOAL, 사용자 보완 지시, 자원·연구·권한·보존 정책은 축약 때문에 누락시키지 않는다.
- 현재 과제의 계획·직전 리뷰·미해결 blocking/reuse 문제부터 읽는다. 필요 자산을 고른 뒤
  해당 SHA, 모듈 승인/결함, 실제 파일·의존성을 확인한다. 색인만으로 재사용을 승인하지 않는다.
- 다른 접근법을 재시도/기각하거나 새 방향을 고를 때는 관련 과거 실패 범위·유효 결과·미해결
  질문의 원문을 확인한다. 새 목표·전략 전환·모순 발견이면 탐색 범위를 넓힌다.
- 이미 확인한 출처를 매 라운드 전부 다시 읽거나 검색하지 않는다. 변경·모순·최신성·미확인
  세부 사항 때문에 필요한 경우만 재확인한다. 필요한 원문을 읽는 것을 절약 대상으로 삼지 않는다.

## 계획과 추가 사고 라운드

- 일반 후속 계획의 기본은 1라운드다. 한 라운드 안에서도 필요한 도구 호출과 깊은 사고는 한다.
  max-think-rounds는 안전 상한이지 채울 횟수가 아니다. 전략·신규성·불명확한 결과 판단은 충분히 조사한다.
- think_more는 추가 세션이 있어야 해결할 중요한 미확인 사항이 있을 때만 쓴다.
  research_notes에 (1) 이번에 새로 확인한 사실, (2) 아직 답하지 못한 질문,
  (3) 답에 따라 달라질 선택/실험/해석, (4) 다음에 볼 구체적 출처를 적는다.
  open_questions에는 이 판단 변화와 확인 대상을 연결한다. 문서 다듬기·분량 증가·이미 답한 질문은 사유가 아니다.
- 추가 라운드에서는 직전 질문과 변경점에 집중한다. 이전 노트 원문은 보존하고 필요 시 읽는다.
  방향을 정할 수 있으면 implement한다. 불확실성을 감추거나 구현·학습 gate를 생략해 1라운드를 맞추지 않는다.

## 같은 실험의 보완 계획

- 가설·자료·metric·성공 기준이 같은 실행 복구/버그 수정이면 기존 계획을 기준으로
  '유지 / 이번 변경 / 미완료 / 회귀 검증'을 작성한다. 전략·문헌조사·baseline을 처음부터 반복하지 않는다.
- 기반 plan 경로와 SHA256, 적용할 amendment 및 수정 범위를 명시한다. inherited 조건은
  원문을 확인한 뒤 연결하며 필요한 입력·분할·metric·확대/중단 기준은 이번 실행 지시에서도 분명히 한다.
  Claude가 읽을 기준 문서를 명시하고 서로 모순되는 계획을 선택하게 만들지 않는다.
- 데이터·전처리·좌표·학습 조건·평가기·표본 선택·판정 규칙의 변경은 영향 범위를 분석한다.
  가설/해석이 바뀌거나 영향을 격리할 수 없으면 정식 계획·충분한 검증으로 확대한다.
- 계획 자체를 바꿔야 할 새 근거가 없으면 형식 보완을 새 과학적 iteration의 이유로 삼지 않는다.

## 변경점 중심 리뷰, 결과 검증은 유지

- 현 계획·보고서·checkpoint SHA·diff·원시 결과·실행 완료 여부·미해결 문제는 반드시 확인한다.
  변경 파일만 보고 데이터/metric/결과 검증을 생략하지 않는다. diagnostic/method/confirmatory의
  필수 GPT 리뷰와 독립 수치 재계산, 정상 사용·누수·실행 무결성 검사는 그대로 유지한다.
- 동일 SHA·입력·설정·평가 경로가 보존된 기존 검증은 출처와 불변 조건을 확인해 재사용한다.
  새 출력은 새로 검증하고, 변경이 전파되는 의존 경로와 회귀 검사를 집중 검토한다.
  출처/불변성 확인 실패, 새 데이터·metric·선택 규칙, 설명되지 않는 결과 차이는 범위를 넓혀 검토한다.
- 구현 결함의 수정 검토에서 관련 없는 과거 코드를 다시 전수 감사하거나 이미 기각한 방법을
  다시 조사하지 않는다. 현재 결론을 막는 문제와 다음 재사용 문제, 선택적 정비를 구분한다.
- 작업이 계속 실행 중이면 종료 여부를 먼저 확인한다. 미완료를 새 가설 실패로 바꾸거나
  중복 GPU 작업을 시작하지 않는다. 실제 학습을 끝내기 전에 보고서를 내는 실행 문제를 숨기지 않는다.

## 측정·적용 경계

- 호출별 전달 바이트 수, 세션 수, 계획/리뷰 표시 토큰을 기존 usage 기록으로 비교한다.
  입력 크기 감소를 구독 사용률 감소와 동일하게 표현하지 않는다. 캐시·도구 문맥·추론·계정의
  다른 작업이 영향을 주므로 실제 절감률은 이후 관측한다. 측정을 위해 모델을 추가 호출하지 않는다.
- 프롬프트/스키마/결과를 임의 길이로 자르지 않는다. 원본 문서·이전 결과·판정은 덮어쓰지 않는다.
- 현재 실행 중인 호출·GPU 실험은 중단하지 않는다. 관리 코드 배포는 안전한 단계 경계에서 하며
  재개 후 다음 호출부터 적용한다. 연구 목표·기존 계획을 새 지시로 supersede할 필요는 없다.
- --auto, 모델 교체, 검증 생략, 임의 GPU 시간/표본 상한, 유료 한도 상향을 이 정책으로 허용하지 않는다.
