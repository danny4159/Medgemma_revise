# 연구 운영 기준

현재 공통 원칙이다. 최종 목표는 GOAL.md, 현재 질문과 승인 범위는 RESEARCH_FOCUS.md,
자원·설치 권한은 RESOURCE_POLICY.md를 따른다. 원 계획·출력·판정은 소급 변경하지 않는다.
과거 일회성 지시는 RESEARCH_HISTORY_INDEX.md를 통해 필요할 때만 읽으며 현재 실행 명령으로 사용하지 않는다.

## 연구 질문과 다음 투자 판단

### 탐색 효율과 실제 투자 선택

iteration 수·테스트 수·GPU 사용량은 연구 진전의 양이 아니다. 중요한 질문의 불확실성을 줄이는 것이 목적이다.
기존 research_track/related_iterations와 Strategy Check를 사용하며 새 필수 JSON 필드·별도 전략 에이전트·
추가 모델 호출은 만들지 않는다. 연구 질문이 같으면 자료·branch가 달라도 이력을 이어받는다.

계획·리뷰의 Strategy Check에 아래 질문 카드 다섯 항목을 짧게 유지한다. 기존 문장을 반복하지 말고
직전 카드의 출처와 바뀐 근거를 적는다. 미확인은 솔직히 표시하며 칸을 채웠다는 이유로 승인하지 않는다.

1. 중요한 문제: 해결하면 어떤 사용 상황·일반적 능력·효율이 달라지는가?
2. 현재 근거: 실제 관찰 / 문헌 주장 / 가설을 구분하고 조건·원문·반대 근거를 연결한다.
3. 쉬운 해결책: 기능 제거·단순 규칙·강한 기존 방법으로 충분한가? 무엇을 얻고 잃는가?
4. 남은 설명: 경쟁 설명과 이를 구분할 최소 비교 또는 개입은 무엇인가?
5. 다음 결정: 양성·음성·불확정이면 무엇에 투자하고 무엇을 보류하는가?

전략 선택은 연구 질문 전환, 강한 baseline 확보, 같은 불확실성 반복, 큰 투자 직전에 한다.
근거 있는 후보 2~3개 이내에서 하나를 선택하거나 범위를 명시해 보류한다. 후보 수를 억지로 채우지 않는다.
평소 버그 수정·계획된 평가에서는 이전 판단의 출처와 변경점만 확인한다. 가까운 선행의 실제 지원 조건,
평가·비교군·공개 구현을 확인하고 논문 주장만으로 해결/미해결을 단정하지 않는다.

### 관찰 계승과 수렴 점검

- 매 리뷰는 질문의 이전 판단 → 추가 증거 → 현재 판단을 적고 줄지 않은 불확실성과 지배 비용을 보고한다.
  비용은 기록으로 뒷받침하며 미계측 비용을 추정 사실로 쓰지 않는다. 운영 복구는 새 가설 검증이 아니다.
- 실험 성공과 다음 투자 가치는 별개다. 시험 설정 / 연구 관찰 / 연구 질문을 구분하고
  실행 유효성 / 성능 개선 / 가설 지지 / 신규 기여 가능성도 각각 판단한다.
- next_task 권고는 집중 / 한정 보완 / 투자 보류·전환 중 다음 행동 하나와 근거·완료 조건을 제시한다.
  모든 결과가 추가 정비로 끝나면 설계를 재검토한다. 실행 실패를 기각으로, 새 후보 탐색을 기존 관찰의
  심화로 포장하지 않는다. 반복 횟수만으로 종료하지 않고 기회비용과 새 증거를 본다.
- 불확정에는 판별력이 있는 확대를 허용한다. 성공을 기대한다는 이유만으로 표본을 늘리지 않는다.
  보류 사유는 자료/실행 문제, 증거 부족, 단순 대안의 충분성, 가치 부족을 구분한다.
  관찰을 보존한다는 것과 계속 투자한다는 것은 다르다. 재개에는 새 근거와 최소 비교가 필요하다.

## 기술 질문·자료·평가의 공동 선택

상위 기술 질문과 경쟁 설명을 먼저 정하고 자료·과제를 선택한다. 임상 사례는 관측 수단이지 기여 자체가 아니다.
실제 관찰 범위를 넘어 일반화하지 않는다. 데이터 이름 변경·모델 순위·기존 loss 이식만으로 신규성을 주장하지 않는다.

자료 접근성·명확한 정답은 실행 가능성의 근거이지 연구 우선순위의 충분한 근거가 아니다. 과제 전환 시
중요한 미해결 문제, 가까운 연구/기존 관찰의 공백, 경쟁 설명을 구분하는 비교, 결과별 다음 결정을 먼저 연결한다.
기존 관찰의 심화인지 별개의 새 탐색인지 명시한다. 완성된 신규성 증명은 요구하지 않되 데이터가 있다는
이유만으로 새 frozen 과제의 실패 수집을 반복하지 않는다.

전문 모델·규칙이 잘된다는 사실은 좁은 실용 과제에서 VLM 투자를 줄일 근거일 수 있지만, 관련 기술 질문
전체의 자동 종료 조건은 아니다. 동일 정보·지도·비용 차이를 밝히고, 판별 가능한 근거를 VLM이 활용하지
못하는 현상을 설명할 중요한 잔여 질문과 최소 개입의 정보 가치가 있는지 판단한다. 반대로 VLM이 실패했다는
사실만으로 그 질문의 신규성·중요성이나 후속 투자를 승인하지 않는다.

### 핵심 자료 조건 먼저

- 상세 모델 실행 설계 전에 질문을 성립시키는 핵심 자료 조건을 확인한다: 실제 schema·정답 의미,
  분석 단위·환자/영상/관계 ID, 적격 사례 존재, 사용 권한과 접근 경로. 확인한 사실과 가정을 구분한다.
- 계획은 read-only를 유지한다. 이미 로컬에 있는 자료의 비변경 조회·집계는 가능하지만 다운로드·파일 생성·
  모델 실행은 구현 단계에서 한다. 직접 확인할 수 없으면 짧은 자료 확인 단계와 조건부 후속만 정한다.
  조건 성립 전에 대규모 모델 설치·완성형 실행기·상세 다중 조건 실험을 만들지 않는다.
- 같은 계획에 한정 적합성 확인과 성립 시 작은 실제 비교를 묶을 수 있다. 핵심 조건이 틀리면 그 설계를
  보류하고 무엇이 달라져야 하는지 보고한다. 파일 하나의 부적합을 연구 질문 전체의 기각으로 바꾸지 않는다.
- 공개 주석에서 관계 정답을 결정적으로 구성하는 작업은 허용된 범위의 정상 구현이다. 같은 환자/대상/공간
  관계가 원 주석으로 보장되고 규칙·변환·검사·제외를 재현 가능하게 기록해야 한다. 변환으로 만든 정답은
  원 제공 정답과 구분한다. 보장할 수 없는 임상 의미나 longitudinal 동일 병변을 추측해 만들지 않는다.
- 비용·규모·대안 경로는 사전에 제한한다. 공개 자료라는 이유로 동의·라이선스·접근 권한을 생략하지 않는다.
  추가 권한·새 전문가 정답·목표 변경은 사용자에게 묻고, 기존 범위의 기계적 자료 구성만으로 재승인을
  요구하지 않는다. 단, --confirm-each-iter의 다음 반복 승인을 우회하지 않는다.

### 평가와 강한 단순 대조

- 공개 정답이 보장하는 범위만 주장한다. 미표기를 음성으로, box 밖/crop 제거를 임상적으로 정상으로
  해석하지 않는다. 전문의가 없는 경우 LLM 합의를 임상 정답으로 대체하지 않는다.
- 일반 입력에 정답 유무·정답 box를 누설하지 않는다. oracle는 원인 분리용이며 실용 대조군과 분리한다.
  합성 개입의 의도된 정답 제공과 비의도적 누수를 구분한다. 환자·원천·학습 노출과 개발/test 재사용을 명시한다.
- 입력·정답·좌표·parser·metric·공식 사용법과 충분한 생성 길이를 검사한다. 출력 형식과 내용 정확도,
  unknown·유보·거부를 구분한다. 잠정 수치를 보존하고 평가가 판단을 막는 부분만 고친다.
  구현자가 parser나 확대 기준을 임의로 바꾸지 않는다. 사후 분석은 원 판정과 별도로 기록한다.
- detector+VLM, encoder+head, 직접 SFT, 재-grounding 등 실제 과제의 강한 단순 대조를 검토한다.
  원본 영상·필요한 도구·정보를 빼서 약한 대조를 만들지 않는다. 학습량·입력·추론 비용 차이를 보고한다.
  모든 검출기를 이기거나 모듈형 대안으로 불가능한 기능을 만들어야 하는 것은 아니다.
- 좌표 출력 / 질문별 영역 선택 / 근거를 이용한 판단을 구분한다. JSON 형식 적응은 시각 능력 개선과 다르다.
  bbox로 만든 위치·개수 질문은 검출+규칙 baseline을 검토하며 임상 reasoning 증명으로 보지 않는다.
- 타 모델은 중요한 관찰의 범위 확인용이다. 모델 특이/공통 현상 후보/미검증을 구분한다.
  여러 모델의 실패를 초기 진입 조건으로 요구하지 않으며 기본 수행 부족은 적합한 대안과 대조한다.

## 탐색의 정보 축적과 단계별 검증

입력·정답·누수·평가 무결성은 필수다. 높은 정답률·100% oracle 정답·확증용 표본 수를 모든 작은
탐색의 진입 gate로 요구하지 않는다. 특정 해석에 필요한 조건이 실패하면 그 해석을 보류하고
분리 가능한 관찰을 판단한다. 조건을 결과에 맞춰 바꾸거나 실패를 숨기지 않는다.

### 탐색용 학습과 연구 질문의 별도 판정

LoRA SFT 등은 가능성·한계를 확인하는 진단 수단일 수 있으며 최종 방법이나 contribution으로 고정하지 않는다.
현재 설정의 무개선을 질문 전체의 실패로 확대하지 않는다. baseline 학습 부족·평가 오류·적응 범위를 구분하고
full fine-tuning을 자동 처방하지 않는다. 음성 자체가 신규 기여는 아니다.

### 진단에서 최소 방법 실험으로의 전환

- 작은 원인 검증: 중요한 유효 관찰과 경쟁 설명이 있고, 최소 개입이 두 설명에서 다른 결과를 예측하며
  결과가 다음 투자를 바꾼다면 검토한다. '일단 학습해 점수가 오르나'가 아니라 개입과 설명을 연결한다.
  내부 원인·최종 신규성·여러 모델 일반화의 완전한 증명을 선행 조건으로 요구하지 않는다.
- diagnostic은 실패 현상/원인 후보를 구분한다. 실제 방법을 개발·학습하면 이름을 diagnostic으로 바꾸어
  method gate를 우회하지 않는다. 탐색 전에 이미 새 기여라고 선언하지 않는다.
- method_stage=pilot은 현재 목표의 observed/validated 한계와 이전 유효 full review,
  evidence·usage_checks·blocking 없음, 중요한 잔여 문제·단순 대안 이후의 구체적 부족함을 연결한다.
  경쟁 설명을 구분할 작은 개입과 공정한 대조를 계획한다. 문헌 아이디어·candidate·CPU 준비만으로 진입하지 않는다.
- 본격 방법 개발·확대: 실험으로 뒷받침된 필요성, 강한 기존 대안 대비 개선 가능성, 독립 확인 설계가 필요하다.
  method_stage=full 및 confirmatory는 validated 근거를 유지한다. pilot 통과만으로 자동 확대하지 않는다.
- decision_contract에 개입 가설/대조, 양성·음성·불확정 행동, 표본·요청·학습량·비용·종료점을 고정한다.
  research_track/related_iterations를 이어받고 이미 고정한 gate를 구현 중 우회하지 않는다.
  문턱을 완화하거나 불확정을 성공으로 바꾸지 않는다. 기계 gate는 근거 상태·무결성 검사이지 신규성 판정이 아니다.

## 진단의 수렴과 비교군 확보

결함의 한정 수정/최소 재측정과 새 실험의 비용·정보 이득을 비교한다. 수정할 수 있다는 이유로 무한 정비하지 않는다.
가까운 강한 비교군의 미설치는 RESOURCE_POLICY의 격리 환경 권한으로 해결할 수 있다. 실제 실패 시도·남은
blocker를 보고하고 약한 대안으로 원 주장을 승인하지 않는다. 쓰지 않을 코드의 전수 복구는 하지 않는다.
blocking_issues를 지우거나 gate를 우회하지 않는다. 필요한 경로만 고치고 불변 검증은 SHA·입력·설정 근거로 재사용한다.

## 판정 범위와 조건부 후속 투자

원 계획의 판정은 유지하고 보류/기각은 실제 검증한 과제·조건으로 한정한다. 기준 미달·검증 부족·연구 가치 부족을
같은 판단으로 취급하지 않는다. 기존 관찰의 설명/반박/미검증 범위를 기록한다. 후속은 결과별로 달라지는 투자 결정,
예상 비용 대비 정보 가치와 종료 조건이 있을 때 이후 별도 계획의 decision_contract에 명시한다.
사후 가설은 탐색이며 원 결과를 재작성하지 않는다. method 진입 gate와 full 리뷰는 유지한다.
--max-attempts는 유효 실험 후 재평가 기준이지 자동 포기 횟수가 아니다. 횟수만으로 자동 기각하지 않는다.

## 사용자 논문 추천

- 가설 단계의 참고문헌을 모두 추천하지 않는다. 유효한 실제 실험에서 비교군 대비 개선이나
  재현되는 진단 결과 등, 그 방향을 더 깊이 탐구할 긍정적 근거가 확인됐을 때 최대 1편을 추천한다.
- success 또는 근거 있는 improve가 기본 대상이지만 상태 이름만으로 추천하지 않는다.
  단순 구현 성공·loss 감소·학습량 부족 가능성·CI 상한에 따른 보완 확대만으로는 부족하다.
  불확정 결과만 있거나 실행 실패·기각한 방향의 문헌은 조사 기록에만 남긴다.
- 최종 contribution·외부 일반화 증명까지 기다릴 필요는 없다. 현재 확인한 범위와 미검증 범위를
  분리하고, 왜 이 논문이 다음 방법·비교·평가 판단에 도움이 되는지 설명한다.
- 문서에 이미 인용했거나 에이전트가 읽은 논문도 추천할 수 있다. 중복 제외는 사용자에게
  전달한 `PAPERS.md`의 추천 이력을 기준으로 한다. 논문과 추천 섹션의 원문·링크를 확인한다.
- 적격 추천은 리뷰의 `paper_recommendation`에 넣는다. 기존 처리 경로가 `PAPERS.md`에 저장하고
  Telegram에 제목·링크·실험 근거·추천 이유/한계·먼저 읽을 부분을 함께 알린다.
  부적격이면 리뷰에 보류 이유를 한 문장으로 남긴다. 추천을 위해 실험을 추가하거나 성공을 과장하지 않는다.

## 단계별 표본·학습·평가 규모

전체 데이터·최대 학습량·여러 seed를 모든 후보에 처음부터 적용하지 않는다.
현재 의사결정을 바꿀 수 있는 규모로 시작해 근거에 따라 확대한다. GPU 회피나 영구적인 작은 pilot 반복을 뜻하지 않는다.

1. 동작 확인: 작은 train 표본으로 입력·정답·mask·gradient·출력·메모리·재개를 검사한다.
   overfit 성공은 학습 경로가 작동한다는 뜻이지 일반화 개선의 근거가 아니다.
2. 가능성 탐색: 대표성 있게 고정한 train/validation 일부와 우선 1개 seed로 실제 생성 개선,
   학습 추세·변동·실패 유형·처리량을 확인한다. 희귀·어려운 유형을 편의상 제외하지 않는다.
3. 규모 확대: 탐색 근거로 유망성이 있거나 표본·수렴 부족을 해결하면 판단이 가능할 때
   필요한 학습량·validation·비교군·seed로 확대한다. 근거가 충분하면 탐색을 생략하고 그 이유를 적을 수 있다.
4. 독립 확인: 설정·checkpoint 선택을 마친 뒤 보존한 확인 집단에서 비교한다.
   논문 수준의 주장은 필요한 정밀도·seed 재현성·추가 데이터셋 근거를 갖춘다. 데이터셋 전체 사용 자체가 필수는 아니다.

- GPT 계획은 각 단계의 질문, 표본/환자/요청 수, 추출·층화·중복 방지, 학습량·seed,
  평가 빈도, 예상 비용, 확대/보완/보류/기각 기준을 기존 Proposed Experiment와 Success Criteria에 명시한다.
  예시 표본 수를 일률적인 상한으로 복사하지 않는다. 규모는 효과 크기·정밀도·변동성과 실측 처리량에 맞춘다.
- 작은 동작 확인을 통과했다는 이유만으로 모든 학습률×여러 seed×전체 epoch 평가를 자동 시작하지 않는다.
  가능성 탐색에서 실제 GPU 실험·출력 평가를 하고, 미리 정한 기준에 따라 다음 단계로 넘어간다.
  조건이 명확하면 같은 Claude 호출 안에서 진행할 수 있다. 단계마다 새 GPT 호출·사람 승인을 강제하지 않는다.
- 매 epoch 전체 validation 생성은 기본값이 아니다. 고정된 층화 validation 일부로 추세를 확인하고,
  사전에 정한 milestone/후보 checkpoint에서 전체 validation을 사용하는 방식을 우선 검토한다.
  전체 평가가 매번 필요한 경우 이유·비용을 적는다. 최종 후보는 같은 검증 범위로 비교한다.
- loss만으로 실제 생성 개선을 판단하지 않는다. 일부 validation의 잡음 때문에 유망한 후보를 조기 폐기하지 않는다.
  작은 표본의 무개선은 구현 오류·학습 부족·정밀도 부족과 구분한다. 짧은 학습의 실패를 전체 방법의 실패로 확대하지 않는다.
- split·층화·seed·평가 일정·확대 기준은 결과를 보기 전에 고정하고 manifest/config로 보존한다.
  탐색용 subset은 독립 test가 아니라 개발 자료다. test를 반복 확인하거나 유리한 표본·seed만 선택하지 않는다.
  확인 집단의 성능을 본 뒤 조건을 변경하면 해당 집단을 개발 자료로 전환하고 새로운 독립 확인 근거를 마련한다.
- 결과 보고에는 현재 도달 단계, 계획 대비 실제 사용량, 확대/보류 이유, 아직 하지 않은 독립 검증을 구분한다.
  필요한 본실험은 충분히 실행하되 더 작은 단계로 판단 가능한 후보에 처음부터 큰 비용을 쓰지 않는다.

## 가설 판정과 코드 보존은 별개

- 공통 관리 코드·정책·프롬프트·테스트는 상위 저장소 main에서 관리하며 연구 접근법의 성공 여부와
  독립적으로 유지한다. research/ 브랜치 전환·복귀로 공통 정책을 되돌리거나 실험과 함께 폐기하지 않는다.
  실험 고유 설정·판정은 해당 연구 코드·iter 기록에 남긴다. 공통 개선은 실패한 접근법에서 나와도
  검토·테스트 후 별도 관리 커밋으로 보존한다. 정책 자체의 결함 수정은 별도의 명시적 변경으로 한다.
- 상위 관리 기능 브랜치는 필요할 때 별도 worktree에서 사용하고 검증 후 main에 반영한다.
  실행 중인 상위 작업 폴더의 브랜치는 바꾸지 않는다. 연구 기록 자동 커밋과 관리 변경 커밋을 분리하고,
  관리 변경 완료 시 선별 커밋한다. push는 사용자가 허용한 원격·범위에서 수행하며 원격 미설정인
  research/ 코드나 Git 제외 결과까지 상위 저장소 push로 백업됐다고 보고하지 않는다.
- 구현 종료·안전한 중단 시 이번 작업의 소스 변경은 성공/실패·리뷰 여부와 무관하게 체크포인트
  커밋으로 보존한다. 커밋은 개발 이력이지 성공 인증이 아니다. Claude는 구현하고 orchestrator가 커밋한다.
- `commit_worthy`는 과거 형식 호환용 기준점 평가이며 저장을 막지 않는다. `reusable_code`는 전체
  스냅샷의 재사용 승인, `code_assets`는 파일·모듈별 승인/수정 필요/기각과 실제 검증 근거다.
  전체 실험이 실패해도 올바른 로더·평가기 등은 모듈 단위로 재사용할 수 있다.
- 실행 전 `code_baseline.json`으로 범위를 고정한다. 기존 사용자 변경·외부 staged 변경은 자동 커밋하지 않는다.
  모델·데이터·결과·5MB 초과 파일·symlink·비밀정보 의심 파일은 제외하고 사유를 기록한다.
  비밀정보 패턴 검사는 완전한 보안 검사가 아니다. 코드에 비밀정보를 넣지 않는다.
- 체크포인트는 `checkpoints/`, `checkpoint.json`과 영구 ref에 보존한다. 최종 리뷰 대상은 `commit.json`과
  `iter_NNN` 태그에 연결한다. `changes.patch`는 구현 전 SHA→리뷰 대상 SHA 비교다.
  `code_review.json`은 검증 결과를 해당 SHA에 연결한다. 브랜치·태그·이력은 자동 삭제하지 않는다.
- stash는 이전 버전의 미커밋 작업·소유 범위가 불명확한 변경 등 예외 상황의 안전망이다.
  전환 시 stash·영구 ref·patch로 보관하고 `CODE_ASSETS.md`에 출처를 남긴다.
  자동 저장 제외 파일이 남아 있으면 stash에 우회 저장하지 않고 전환을 보류한다. 원본은 유지한다.
  results/ 등 제외 산출물은 별도 파일로 유지한다. 로컬 Git 커밋은 외부 백업이나 원격 push가 아니다.
- 새 접근법은 최근 재사용 승인 커밋을 기반으로 한다. 특정 승인본이 필요하면 계획의
  `reuse_iteration`으로 선택한다(0은 자동). 같은/기존 브랜치를 잇는 경우에는 그 브랜치를 유지한다.
  일부 모듈만 쓸 때는 계획의 `reuse_assets`에 전체 commit SHA·개별 파일 경로·의존 파일·이유·
  required_checks를 명시한다. orchestrator가 실제 blob을 확인하고 Claude 실행 전에 선별 반입한다.
  원본 누락·경로 이탈·symlink·기존 파일 충돌이면 시작을 보류한다. 임의로 덮어쓰거나 재구현하지 않는다.
  이미 복구된 동일 내용 파일은 명시적 manifest로 이번 작업에 편입할 수 있다.
  반입 후 Claude는 관련 테스트·입력 연결을 실제 검증하고 GPT가 승인 범위를 판정한다.
  manifest가 없는 기존 계획은 자동 반입하지 않는다. 필요한 파일을 지정해 재계획한다.
- 결함 있는 보관본을 그대로 신뢰하지 않는다. `reuse_issues`를 해결하고 현재 입력과 provenance를
  확인한 뒤 재사용한다. 성공한 코드·유효한 음성 결과·원본 기록을 지우거나 덮어쓰지 않는다.

## 검증과 방향 전환

- success: 계획한 기준 충족. improve: 구체적인 개선 근거 있음.
  inconclusive: 표본·정밀도·수렴 등으로 결론 불충분.
  execution_failed: 실행·데이터·환경 오류로 유효한 검증을 못 함.
  abandon: 유효한 근거와 기회비용을 검토해 특정 설계에 대한 투자를 중단함.
- `valid_experiment=true`는 계획의 가설을 해석 가능한 방식으로 실제 검증했을 때만 쓴다.
  준비·코드 검사만 했거나 실행 무효면 false다. 유효한 실험도 정밀도가 낮으면 inconclusive일 수 있다.
  과거 미분류 결과를 자동으로 실패/유효 실험으로 재해석하지 않는다.
- `failure_scope`에 실패/불확정이 적용되는 데이터·설계·학습 조건을 적는다.
  작은 head 실패를 전체 표현·anatomy·경량 학습 가능성의 실패로 일반화하지 않는다.
- 리뷰 문제는 `blocking_issues`(현재 결론 무효), `reuse_issues`(재사용 전에 수정),
  `deferred_issues`(추후 견고성 개선)로 나눈다. 선택적 보완 때문에 유효한 실험 전체를 실패 처리하지 않는다.
  `goal_progress`에는 목표에 관해 새로 알게 된 것과 아직 검증하지 못한 것을 쓴다.
- `--max-attempts`는 유효한 실험 누적 후 재평가 기준이지 자동 포기 횟수가 아니다.
  계속하거나 기각한 설계를 다시 시도하면 `continuation_reason`에 이전 기각 범위, 새 근거,
  기대 정보 이득과 중단 기준을 쓴다. 인프라 수정/실행 실패를 이 횟수에 넣지 않는다.
- DONE은 목표의 실제 충족 근거가 있을 때만 사용한다. 대안이 소진됐거나 목표를 바꿔야 한다면
  완료로 포장하지 말고 NEEDS_HUMAN으로 판단을 요청한다.

## 중단 후 사용자 보완

- 사용자 보완 지시는 이전 계획보다 우선하되 목표·권한 범위를 임의로 넓히지 않는다.
  보완 설정만으로 실험을 재개하지 않는다. --confirm-each-iter의 승인 대기를 보존한다.
  담당만 변경할 때는 안전 중단·보존 후 --handoff-engineer로 같은 iter를 인계한다.
  agent/RESUME.md 또는 --replan으로 전달하면 기존 미완료 반복은 superseded로 보존하고 새 반복에서
  GPT가 재계획한다. 실패·완료 판정을 조작하지 않는다. Claude는 새 세션으로 시작한다.
- GPT는 이전 계획·부분 결과·보존 코드·한계 기록을 읽고 무엇을 유지/보류/변경했는지 명시한다.
  단순 중단이며 보완 지시가 없으면 기존 단계·세션부터 이어간다.
- 조사 라운드의 research_notes와 open_questions를 다음 라운드에 전달한다. 기존에 확인한 사실을
  다시 미확인으로 적을 때는 이전 출처·버전과 대조해 불일치 이유를 설명한다.
