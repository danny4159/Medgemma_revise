## 진입·검증 기준

첫 계획에서 가까운 선행의 주장/평가 범위/미검증 조건과 위 경쟁 질문 2~3개를 비교하고,
첫 공식 모델 실행·평가 설계를 구체화한다. CURE 공식 base(1.5가 아닌 medgemma-4b-it)는 모델 카드와
config로 재확인한다. 논문 조건 재현 확인과 새로운 조건의 확장 검증, checkpoint 시스템 비교와
동일 데이터/예산 방법 비교를 구분한다. 현상을 분리할 자료·정답·평가기와 결과별 판단을 고정한다.
한정 검사가 준비되면 실행하고, 의미 있는 관찰이 있으면 최소 개입도 허용한다. 새 loss·전체 재학습을
먼저 발주하거나 문헌/추론 진단만 무기한 반복하지 않는다. 작은 표본의 불확정만으로 다른 분야로 떠나지 않는다.
재사용 코드의 필수 검증과 의미 있는 표본 확대는 유지하며, 일반적인 detector보다 bbox 점수가 낮다는
이유만으로 판독문 개선 후보를 탈락시키지 않는다. 연구 가치는 최종 판독과 강한 기존 판독 대조로 판단한다.

## 보존·적용

새 수동 결과는 오케스트레이터 리뷰를 거치지 않은 입력 증거다. 파일 존재·provenance·라벨/평가 범위의
한정 확인 없이 approved/validated로 승격하지 않는다. 기존 adapter 경로는 수동 protocol과 iter_012에 있다.
과거 단순 검출 투자의 보류를 판독문 전이 연구의 기각으로 옮기지 않는다. MRI 원본과 실패 범위도 보존한다.
연구 코드 branch 선택·반입·checkpoint는 기존 오케스트레이터가 담당한다. 사용자 untracked 수동 파일을
지우거나 모든 관련 코드를 자동 승인하지 않는다. 이후 반복도 같은 질문·관찰 계승 기준을 따른다.
기존 구현 담당 Codex와 smart autonomy·사용량 정책을 유지하고 GPU 0,1을 허용한다. 기본 환경·모델 캐시는
변경하지 않는다. 설치가 필요하면 사용자에게 먼저 알린다. 중요 가치 선택·권한이 필요한 경우만 질문한다.
